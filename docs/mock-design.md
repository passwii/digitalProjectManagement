# Mock Design：Spark 与演示站高保真模拟设计方法

## 目标与范围

Mock Design 面向 Spark、Stream Monitor 及后续的演示站点。它把固定或生成的模拟数据，组织成一个可信、连续、可交互的虚构运行世界，再用丰富的视觉模型和动效把这个世界呈现出来。

演示站的目标是让人看见产品能力、场景规模和技术表现。不要把传统业务后台的克制当成视觉上限；可以使用高密度数据、强烈的场景视觉和多层特效。效果需要有清楚的层级和状态来源，让观众能读懂眼前发生了什么。

本指南补充而不替代 `DESIGN.md`：数科云办公主工作台继续遵循其 Graphite Workbench 体系；每个独立演示站保留自己的视觉身份和局部令牌。具体资产限制以对应站点的 `AGENTS.md` 约定为准，例如 `/stream-monitor` 使用 CSS/SVG 合成画面，不向 `public/` 添加视频或图片素材。

## 核心原则

### 1. 先建立一个可追踪的场景世界

开始界面设计前，先写一份简短的场景设定，明确：

- 站点在展示什么行业、组织和运行环境；
- 主要地点、业务对象、设备、人员、事件和能力之间的关系；
- 当前演示时刻、统计窗口、时区和数据快照口径；
- 哪些对象会被多个页面共同引用，以及它们的稳定 ID。

页面应当是在观察同一个世界的不同切面。总览里的设备、门店、人员或事件，进入列表和详情后仍是同一批对象，名称、ID、状态、时间和相关指标保持一致。

### 2. 让数据关系产生拟真感

数据的可信度来自关系与分布，不来自小数位数或记录总量本身。

- 让图表、KPI、列表、告警和详情由同一份基础记录推导，避免每个组件各写一组互不相干的数字。
- 使用符合场景的单位、时间范围、状态组合和名称；避免整屏数值都过于整齐、重复文本或同一种状态占满所有记录。
- 设计常态、忙时、异常、处置和恢复等不同状态，让少量异常嵌在大量正常数据中，并在相关页面上留下连贯痕迹。
- 允许数据密集和细节丰富；名称、编号、时间戳、备注和趋势应共同支持场景，而不是只填充版面。

### 3. 用确定性模拟制造运行感

模拟界面可以表现为持续运行，但表现应来自可控的数据和状态变化。

- 小型站点可用类型明确的静态 fixture；数据量大或需要跨页关系时，使用确定性生成器和数据校验。
- 采用「场景设定 → 基础数据集 → 页面投影 → 视图渲染」的链路。页面组件消费有类型的数据，不在渲染阶段随意拼接大量临时数组。
- 需要动态展示时，准备基准快照和确定性帧，由统一时钟推进。计数器、图表、活动流和设备状态应从同一帧读取。
- 支持暂停或静态展示；截图模式与减少动效偏好下，界面落在稳定、完整的终态。
- 不用每次渲染都变化的随机数制造实时感；同一个场景应能重复演示。

### 4. 让特效成为场景的一部分

默认采用丰富的效果层次。一个核心页面通常应有一个主视觉模型，并组合若干互补表现，例如：

- 环境层：空间光、网格、粒子、流动纹理或深度氛围；
- 场景层：地图、拓扑、设备舱、视频分析画面、数据地形或其他站点专属模型；
- 数据层：动态曲线、频谱、热力、粒子流、计数滚动或状态脉冲；
- 交互层：悬停揭示、筛选重排、时间切换、视角变化和页面转场。

不要求每页使用相同组合，也不限制同屏效果数量。效果应与场景和数据发生联系：告警等级影响提示强度，数据帧推动图表变化，设备状态改变相应模型。避免只重复卡片淡入、通用光晕和无关循环动画，让不同页面有不同的视觉高潮。

### 5. 共享方法，每站建立自己的视觉身份

可复用数据生成、图表基础、动效控制和调试工具；不要因此让所有演示站变成同一套深色侧栏加卡片网格。

每个站点单独定义视觉简报：一句话场景隐喻、主色与数据色、材质、图形母题、主视觉模型、动效节奏和页面构图。优先让观众从首屏和关键模型识别站点身份，再让通用控件退到辅助位置。

令牌按界面命名空间组织。`/stream-monitor` 沿用 `--av-*` 与 `AV_MOTION`；Spark 和未来站点使用自己的语义令牌。颜色、时长、缓动和层级集中管理，组件引用令牌，不散落裸值。

### 6. 让演示身份清楚、存在感轻

视觉上可以高度拟真，数据在技术上仍应诚实。

- 为模拟数据保留明确的数据锚点或快照身份；全站选择一个稳定位置说明，不必在每张卡片重复提示。
- 没有真实后端或设备连接时，不把本地模拟帧描述成真实线上实时数据。
- 展示状态、响应和操作结果可以完整模拟，但不能让它们写入业务数据库、审计记录或外部系统，除非该演示站另有明确授权与设计。

## 页面设计流程

1. **写场景设定：**明确这个站点展示的世界、受众、时间锚点和主视觉隐喻。
2. **画数据关系：**列出实体、ID、字段、状态、指标来源和跨页关系；决定用静态数据还是确定性生成器。
3. **排演示节奏：**规划首屏主视觉、关键数据、异常线索、深入查看和状态变化，让浏览页面像进入一段产品演示。
4. **设计效果图谱：**按页面列出环境、场景、数据、交互四类表现及其触发状态，避免每页只换标题和数字。
5. **定义站点令牌：**统一局部颜色、表面、字体、间距、组件尺寸和动效参数，同时保留站点之间的差异。
6. **实现连贯交互：**筛选、切页、暂停、查看详情和状态变化都要反馈到同一份场景状态中。
7. **检查展示质量：**走查所有页面和窄屏；核对跨页数据与时间；检查静态模式、减少动效、键盘操作、文字可读性和效果表现是否完整。

## 新站点简报模板

新建演示站时，先填写以下内容，再进入页面实现：

```text
站点名称与路径：
一句话场景隐喻：
演示世界与组织：
场景时间、时区与数据锚点：
核心实体与稳定 ID：
主要运行状态与异常事件：
各页面的数据投影：
主视觉模型：
环境 / 场景 / 数据 / 交互效果：
站点专属颜色、材质与动效令牌：
模拟数据的说明位置：
静态模式与减少动效行为：
站点专属资产限制：
```

## 现有站点作为参考

- `/spark` 已有云电竞运营、门店、算力、计费、内容、安全和运维数据，可在此基础上加强共同实体、时间线与场景主视觉。
- `/stream-monitor` 已有确定性 JSON 生成、页面数据投影、统一数据锚点、预设动态帧、波形与检测框等合成视觉，可作为模拟数据与效果联动的实现参考。

两站提供可复用经验，不构成后续站点必须复制的配色、布局或视觉模型。
