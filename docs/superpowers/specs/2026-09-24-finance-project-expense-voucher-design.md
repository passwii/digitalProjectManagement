# 项目支出转财务凭证设计

## 现状与目标

项目支出属于项目管理成本域，金额存储为 `Float`，一条记录包含项目、人员/历史科目文本、金额、日期、说明和审批状态。财务账属于独立账套，金额以 Decimal 保存，凭证必须由启用末级科目组成并通过既有审核、过账状态机。

当前两个域没有自动映射关系。财务工作台明确提示项目支出不会自动生成会计凭证；Stage 0 冻结蓝图要求未来如需入账，走可核对的“项目成本 → 会计凭证”转换。该阶段提供人工确认后的逐笔转换，不假设项目成本文本可以推导借贷科目、支付方式或现金流项目。

## 方案选择

1. **逐笔手选借贷科目，生成草稿凭证（采用）**：财务人员在当前账套内选择一笔已批准项目支出、期间、日期、借贷科目及科目要求的辅助核算；服务端按原支出金额生成一张草稿凭证，并保留不可重复的来源关联。账务判断由人员确认，既能形成可追溯的会计凭证，也不把项目成本字段当作会计规则。
2. 配置支出类别到科目的映射后批量生成：减少逐笔操作，但现有 `Expense.subject` 兼容人员名称和历史分类，不是稳定的会计类别；且支出记录没有现金、应付等结算方式，需要先扩充业务模型和配置治理。
3. 只提供已审批支出的核对清单导出：风险最低，但仍需会计人员在外部重复录入凭证，不能完成冻结蓝图提出的可核对转换。

采用方案 1。

## 页面与交互

- 在财务工作台增加“项目支出入账”页签，账套上下文沿用当前已选账套；页面明确显示账套编码、名称，避免跨账套误操作。
- 列出当前用户可读取项目中的已通过或特批支出，并显示项目编号/名称、来源记录编号（本阶段使用 `Expense.id`，当前模型没有业务单号）、项目支出日期、金额、说明、审批状态及关联凭证状态。API 只提供 `by_id`，没有经办人显示名；本阶段不展示经办人名称。
- 待入账记录可逐笔打开转换弹窗。弹窗显示完整原始支出摘要、当前账套编码/名称及来源项目；财务人员选择仍开放的会计期间、凭证日期、借方科目、贷方科目，并补齐所选科目要求的辅助核算与现金流项目。
- 原支出日期落在一个开放期间时，默认选中该期间并将凭证日期设为原支出日期；否则要求人员选定开放期间和日期。手动设置的凭证日期与原支出日期不一致时，页面显示会计判断确认提示。
- 金额不可编辑，直接取已审批支出的金额并按分转换成财务 Decimal；摘要可编辑并默认带项目编号和来源记录编号（`Expense.id`）。服务端只保存草稿，不会自动提交、审核或过账。
- 已有来源凭证的支出显示凭证号和状态；凭证被删除时来源关联随凭证删除，允许重新生成；作废凭证保留来源关联并阻止再次生成，避免无提示地重复入账。
- 若来源凭证在另一账套，仅提示“已在其他账套转换，不能重复入账”，不向当前账套用户泄露其无权读取的凭证号和账套资料。
- 转换成功后刷新列表和凭证列表，并使用 API 返回的 `voucher_no` 提示凭证号、草稿状态及需继续审核过账。

## API、数据与事务

- `GET /finance/project-expenses`：要求当前账套头和账套级财务读取权限；支持项目、审批状态、期间日期、分页筛选；默认只列 `approved`、`exception`，并附项目摘要和来源凭证摘要。系统管理员可读取活动项目范围内的数据；其他财务人员仍须通过既有项目读取权限，不能因账套角色获得未授权的项目资料访问权。其他账套的来源链接只回传已占用状态，不回传敏感账套或凭证信息。
- `POST /finance/project-expenses/{expense_id}/voucher`：要求 `finance_clerk` 或 `finance_manager` 账套角色，系统管理员可操作；请求仅包含期间、凭证日期、借贷科目、分录辅助核算/现金流项目和摘要，不接受客户端金额或账套 ID。账套通过 `X-Account-Book` 确定。
- Voucher 增加可空、唯一的 `source_expense_id`，以外键关联项目支出；唯一性全局生效，不允许同一条项目支出落入多个账套。转换端点在同一事务中锁定期间、核验开放状态和支出审批状态、读取原金额、验证科目以及当前账套内对应类型的辅助资料、分配当前期间的 `记-####` 凭证号、创建来源为 `project-expense` 的草稿凭证与分录、写入审计日志。唯一约束作为并发重试时的最后防线。
- 已关联支出无论在当前账套还是另一个账套，都不能再次生成第二张来源凭证；不匹配账套的请求不会创建数据。该约束在数据库和服务端同时落实。
- 项目读取权限沿用既有项目 RBAC；财务账套和会计期间权限继续由既有 `_book_header`/`require_finance` 强制执行。所有成功转换使用既有审计机制。

## 边界与错误处理

- 只有 `approved` 和 `exception` 状态可转换；待审批、驳回及其他状态不允许创建财务凭证。
- 不根据 `Expense.subject` 推导会计科目，不修改原项目支出，不复制附件，不汇总多笔支出，也不自动生成现金流分类。
- 账套角色没有项目访问权的人员不能查询对应支出；管理员查询也仅包含未软删除项目。
- 已有凭证时返回已关联凭证信息并使用冲突状态，不创建重复凭证。期间关闭、科目无效、辅助核算缺失、日期越界、金额无效分别返回既有财务错误结构并回滚事务。
- 本阶段不做批量导入/映射规则、自动审核或过账、跨账套项目归属配置、项目支出编辑/删除以及第三方总账同步。

## 验收标准

- 财务工作台选定账套后，财务人员只看到其有项目读取权的已通过/特批支出；切换账套或项目筛选不会混用旧数据。
- 创建凭证时借贷合计相等且等于原始支出金额；客户端无法覆盖金额或账套。
- 必填辅助核算和现金流资料缺失时服务端拒绝并不写入任何记录。
- 相同来源支出并发或重复提交时最多产生一张凭证；创建后显示来源支出和凭证状态。
- 生成结果始终为草稿，后续提交、审核、过账沿用原财务状态机。
- 迁移可升级和回退；静态检查、构建与相关自动化验证完成。
