# 设备资产自定义批次与空批次清理设计

> 日期：2026-09-29  
> 范围：公司设备资产的批次命名、设备录入与导入时复用批次、批次名称维护、空批次删除

## 背景

当前公司设备资产有独立的 `equipment_batches` 表，批次以数据库自增 ID 识别。入库表单每次提交都会创建新批次；台账导入也会自动新建一个批次；新建单件设备的 API 不支持选择批次。因而同一批产品分次录入会被拆成多个批次。永久删除设备时，所属批次按现有行为保留；全部设备删空后，没有批次删除入口。

批次还承载来源、供应商、采购单号、发票号、验收状态和备注。新批次身份不应复用这些采购元数据字段，也不能因复用批次而覆盖既有信息。

## 目标

1. 用户可为新批次指定名称，并在后续设备录入或导入时选择复用该批次。
2. 一份 CSV/Excel 导入文件中的设备统一进入所选的一个批次。
3. 复用批次时保留原批次元数据；新增设备继承批次当前验收状态。
4. 管理员可更正批次名称，并显式删除已无设备的批次。
5. 后端对批次名称、权限、关联设备和并发操作执行最终校验并写入审计记录。
6. 批次改造完成后，再与用户另行讨论设备详情及流转信息的清晰度；本次不调整这些界面。

## 设计决策

### 1. 批次身份和名称

- 为 `equipment_batches` 增加必填 `name`（最长 128 个字符）。现有 `id` 保留并继续作为稳定的内部 ID。
- 保存前去除名称首尾空白；名称不得为空。名称按不区分大小写的全局唯一规则校验，避免大小写不同的近似重复名称。数据库使用 `lower(name)` 唯一索引作为并发写入时的最终约束。
- 页面和导出内容显示“`<name> · 批次 #<id>`”，既让用户识别自定义批次，也保留稳定编号用于排查和历史兼容。
- 新增数据库迁移：先增加可空列，为既有记录回填 `批次 #<id>`，再设为非空并建立不区分大小写的唯一索引。来源、供应商、采购单号、发票号、验收状态、备注及设备/流水关联保持不变。
- 管理员可重命名已有批次。重命名仍执行 trim、非空、长度和全局唯一校验；成功后写入 `rename_equipment_batch` 审计记录。名称冲突返回可读错误，不修改原名称。

### 2. 创建设备并加入批次

- 继续使用现有资产页面“入库”表单作为设备录入界面；件数设为 1 即可录入一件设备，多件录入仍共享同一批次。不另建第二套单件录入表单。
- 表单提供“新建批次 / 加入已有批次”两种模式。
  - **新建批次**：填写必填批次名称，并保留现有来源、供应商、采购单号、发票号、验收状态和批次备注字段。提交时在同一事务中新建批次和设备。
  - **加入已有批次**：使用可搜索的批次选择器，候选项显示名称、编号、来源和验收状态。已有批次的采购元数据和验收状态只读，不随设备录入而覆盖。
- 新增设备的初始状态继承所选批次状态：`pending_acceptance` 批次对应待验收设备；`accepted` 批次对应可用设备。验收仍通过现有批次验收操作完成，并按现有规则更新待验收设备与事件。
- 服务端在写入时校验批次存在且有效，并对复用批次加锁，避免与批次删除并发竞争。既有 `POST /equipment-assets/inbound` 的单次多设备原子行为继续保持。
- 单件建档 API `POST /equipment-assets` 增加可选 `batch_id`。传入时，服务端锁定并校验批次后关联设备，且继承其验收状态；省略时保持现有无批次单件建档语义。前端不新增第二套单件建档界面，页面录入仍统一使用“入库”表单（件数为 1 即单件录入）。

### 3. 整份导入复用一个批次

- 导入弹窗在选择文件前提供与入库一致的“新建批次 / 加入已有批次”选择。
- 选择已有批次时，导入请求携带其 `batch_id`，整份文件全部设备加入该批次，并继承该批次验收状态。批次元数据保持不变。
- 新建批次时，弹窗要求填写自定义名称；来源默认使用现有的 `导入 <文件名>`，验收状态默认 `accepted`，保持当前导入默认行为。若用户需要待验收设备，可在批次选择区域显式设置新批次验收状态；批次采购元数据沿用入库表单中已支持的字段，不强迫用户为普通台账导入填写采购信息。
- 不在导入模板中新增批次列；一个文件不拆分到多个批次。导入模板的设备字段、按表头识别列、逐行校验及忽略状态/使用人等流转列的既有契约保持不变。
- 服务端先解析并校验整个文件，再在一个事务内创建（如选择新建）或锁定（如选择复用）批次、写入全部设备和事件、记录审计。任何行校验失败时不创建空批次，也不留下部分设备。
- 成功响应继续返回 `batch_id` 和 `created`，可增加批次名称以便前端显示成功提示。导入时创建新批次的名称冲突应返回明确错误，并允许用户选择已有批次后重试。

### 4. 批次列表、查询和设备数

- 批次列表显示自定义名称、编号、来源、供应商、采购单号、发票号、验收状态和当前设备数；保留查看设备明细和现有分页。
- 增加服务端批次名称/编号/来源搜索参数，复用同一批次列表 API，为管理列表和选择器提供分页结果。选择器可搜索所有批次，不局限于当前已加载的一页。
- 设备数按当前 `equipment_assets` 关联记录计算；设备被永久删除后数量随即减少。零设备批次明确显示“空批次”。
- 台账导出中的“所属批次”改为自定义名称加批次编号，避免仅显示来源造成同批次难以辨认。导入仍忽略导出的所属批次列，批次选择由导入弹窗负责。

### 5. 空批次删除

- 设备删除后批次不自动删除；空批次继续在列表中可见，只有管理员显式执行删除。
- 仅当批次当前没有任何关联设备且没有引用该批次的设备流水时，允许删除。正常设备删除会一并删除其事件；同时校验设备和事件，是为了防止遗留引用导致外键错误或历史数据丢失。
- 列表仅对零设备批次展示管理员删除入口。点击后打开二次确认，显示批次名称、编号以及“当前没有设备”；确认后才调用删除 API。
- 删除 API 要求管理员权限，锁定批次后再次检查设备和事件引用；有设备或流水则返回冲突错误，不尝试级联删除设备、事件或采购元数据。该锁与设备录入复用批次时的行锁配合，防止删除检查与新增设备交错。
- 成功删除后写入 `delete_equipment_batch` 审计记录，至少保留批次 ID、名称、操作者与删除时间。前端刷新批次列表及其计数。非管理员无法看到删除操作，服务端仍独立拒绝无权限请求。

## API 与数据流边界

- 批次创建、名称重命名和设备关联只由设备资产 API 写入；前端不通过先创建后多次提交来拼出一个批次。
- 入库 API 能表达两种互斥意图：提供新批次字段创建批次，或提供已有 `batch_id` 复用批次。两种意图同时提交或都未提交时返回验证错误；空设备列表继续拒绝。
- 导入 API 以 multipart 字段接收文件和批次选择/创建参数。新建与复用的互斥规则、名称唯一性和验收状态继承在服务端统一实现。
- 批次列表返回分页数据及当前设备数；查询参数用于搜索。批次详情继续返回设备明细，并加入名称和当前设备数。
- 新增管理员批次重命名及删除路由；删除路由仅删除空批次记录，不删除关联资产。

## 错误处理与兼容性

- 名称为空、过长、重名、批次不存在、角色无权限、导入文件行校验失败和非空批次删除均返回可读的中文错误。
- 唯一索引冲突转换成“批次名称已存在，请选择已有批次或更换名称”，避免并发创建时泄露数据库错误。
- 迁移只为旧批次补名称，不改变资产批次 ID 或验收/历史状态。
- 列表、选择器和导入成功提示使用自定义名称；已有客户端仍可依靠 `id` / `batch_id` 操作批次。
- 审计记录应与批次数据变更同事务提交，避免数据成功而审计失败或相反。

## 验收与测试

### 后端与迁移

- 迁移测试确认历史批次逐条命名为“批次 #原 ID”，名称非空且不改变资产关联；新唯一索引拒绝不区分大小写的重名。
- 新建批次支持 trim 后名称；空名称、过长名称及重复名称被拒绝，且冲突不留下空批次。
- 分两次入库加入同一批次，设备拥有相同 `batch_id`；来源/供应商等原元数据不变。
- 复用待验收批次的新设备为 `pending_acceptance`；复用已验收批次的新设备为 `available`。
- CSV 与 XLSX 导入均能将整份文件加入指定批次；导入原子校验失败时，批次和资产数量不变；创建批次的名称冲突有明确错误。
- 普通用户不能重命名或删除批次；管理员重命名成功写审计，重名失败并保留旧名。
- 空批次可删除并产生审计；存在设备或遗留事件时拒绝删除；删除最后一件设备不会自动删批次。
- 并发边界通过事务锁与数据库唯一约束校验：批次复用与删除不能同时成功造成孤儿资产。

### 前端

- 入库表单可在新建/复用批次模式间切换；已有批次选项显示名称、编号、来源和验收状态；提交内容只包含相应模式的字段。
- 单件录入（件数为 1）和多件录入均进入选定的同一批次。
- 导入弹窗要求选择批次模式；整份导入结果提示批次名称/编号；模板原设备字段仍可下载。
- 批次列表能搜索、分页，显示设备数、名称及空批次状态；重命名可见且冲突错误可读。
- 空批次删除先显示确认窗口；取消不发请求，确认后删除并刷新；非空批次无删除按钮。
- 运行资产页面 DOM 测试、设备资产 API 测试及项目规定的前端/后端完整检查。

## 非目标

- 不重新设计设备详情、设备台账列、状态转换、设备事件时间线或统计口径；相关可读性问题在本次批次功能完成后另行讨论。
- 不把一份导入文件拆分至多个批次，也不通过导入模板逐行填写批次。
- 不因删除设备自动删除所属批次。
- 不改变当前设备永久删除、设备流水不可变、验收、领用/借用/归还、维修、报废或作废的既有规则。
