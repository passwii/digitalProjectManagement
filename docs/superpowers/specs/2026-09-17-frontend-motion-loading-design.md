# 前端加载反馈与高级动效设计

日期：2026-09-17

状态：已确认，待实施计划

## 1. 目标

本轮前端优化解决两个问题：

1. 在模块切换、数据加载、筛选、分页、刷新和提交等异步动作中，提供统一、清晰、可感知的系统运行状态。
2. 使用 Framer Motion 提升导航、页面切换、弹层、数据展示和图表的动效质量，同时保持商务控制台应有的克制和效率。

本轮不改变业务接口、权限、URL 状态、表单校验和审批规则。

## 2. 已确认决策

- 采用 Framer Motion，包名为 `framer-motion`。
- 不新增其他动画依赖。
- 真实异步动作不被人为拖延；界面状态最短可见约 450ms，避免快速响应时加载效果一闪而过。
- 加载反馈覆盖模块导航、首次加载、筛选、分页、刷新、保存、审批、删除和导出。
- 普通 Tab 切换和弹窗打开只做动效，不强制增加 450ms 等待。
- 动效方向为克制的商务控制台风格：位移幅度小、时长短、层级清晰，不使用大幅横滑、炫技式弹簧或持续背景动画。
- 所有动效必须支持 `prefers-reduced-motion`。

## 3. 现状与改造边界

当前已经具备：

- 路由级 `loading.tsx` 和页面内 `LoadingBlock` 骨架。
- `useAsyncData` 统一处理请求加载、取消、错误和重试。
- 弹窗、抽屉、Toast、按钮忙碌态和基础 CSS 入场动画。
- `Shell` 中基于 `pathname` 的轻量路由入场动画。

当前不足：

- 导航切换没有全局进度反馈。
- 快速响应时骨架或忙碌态几乎不可见。
- 动效分散在 CSS、页面组件和弹窗组件中，没有统一节奏。
- 数据刷新有“更新中”文字，但缺少统一的活动状态和视觉反馈。
- KPI、图表和导航选中态没有连续、可复用的 Motion 表达。

本轮改造只服务上述问题，不顺带重构业务组件、不改后端接口、不改变页面信息架构。

## 4. 架构

### 4.1 MotionProvider

在 `app/(dashboard)/layout.tsx` 内挂载 `MotionProvider`，负责：

- 管理全局活动状态和顶部进度条。
- 为路由页面提供统一的 `AnimatePresence` 容器。
- 向业务组件暴露 `useActivity`。
- 读取 `useReducedMotion` 并向下传递动效降级策略。
- 使用 `LazyMotion` 与 `domAnimation` 控制 Framer Motion 的初始体积。

业务页面只使用通用组件和 hook，不直接创建全局活动状态。

### 4.2 Activity 管理器

新增 `useActivity`，用于登记一个可见异步动作：

```ts
const finish = beginActivity({
  label: "更新项目台账",
  scope: "content",
});

try {
  await task();
} finally {
  finish();
}
```

活动管理器遵循以下规则：

- 每个活动拥有独立 token，避免并发请求互相覆盖。
- 活动总数为 0 时，顶部进度条进入完成和淡出阶段。
- 单个活动真实结束后，界面完成态至少保留到开始后 450ms。
- 真实请求超过 450ms 时立即按真实结束时间关闭，不额外增加等待。
- 请求失败、主动取消和组件卸载都必须调用 `finish()`。
- 并发活动未全部结束时，进度条不提前关闭。
- 过期请求不得关闭当前页面或当前筛选条件下新创建的活动。

450ms 是最短可见时长，不是网络延时，也不改变接口返回、Toast 内容或数据写入时机。

### 4.3 ActivityBar

`ActivityBar` 固定在顶栏下沿，覆盖内容区宽度：

- 初始阶段从左向右推进，使用现有 `--brand` 蓝色。
- 真实请求较慢时进入缓慢推进状态，不伪装精确百分比。
- 全部活动结束后快速推进到末端，再以约 220ms 淡出。
- 保留 `role="progressbar"` 和简短可访问标签。
- reduced-motion 下取消位移动画，保留静态进度条和文字状态。

### 4.4 异步接入

`useAsyncData` 内统一接入 Activity 管理器：

- 首次加载：活动标签取 `LoadingBlock.label` 或页面默认文案。
- 筛选、分页、刷新：活动标签为“更新中”，现有内容保持可见。
- 错误：先结束活动，再显示 `LoadFailed`。
- 取消：结束对应活动，不显示错误，不影响新活动。

业务提交动作通过 `useActivity` 包裹：

- 按钮内显示旋转状态。
- 顶部进度条同步亮起。
- 请求结束后再触发成功 Toast、失败 Toast 或弹窗状态变化。

## 5. 页面切换设计

页面切换采用“顶部进度 + 内容过渡 + 骨架接力”三层反馈。

### 5.1 路由开始

- 主导航点击后立即登记一次导航活动。
- `MotionProvider` 通过统一的全局点击监听识别同源站内链接，并登记导航活动；业务页面不额外包裹 `MotionLink`。
- 新标签页、下载、外链、带修饰键的点击和锚点不触发导航活动。
- 浏览器前进和后退通过 `pathname` 变化触发同等反馈。

### 5.2 内容过渡

使用 Framer Motion `AnimatePresence`：

- 旧页面：约 140ms 淡出并上移 4px。
- 新页面：约 220ms 淡入并回落到原位。
- 总时长与顶部进度条形成连续节奏，不让用户等待两次。
- 页面主体使用 `pathname` 作为 key；查询参数变化仅触发局部活动状态，不触发整页退场。

### 5.3 骨架与真实内容

- 首次进入页面继续使用现有骨架结构。
- 骨架最短可见 450ms；真实数据更慢时继续显示。
- 数据到达后骨架与内容使用约 180ms 的交叉淡入。
- 筛选、分页和刷新不覆盖表格，保留旧内容并显示局部更新状态。
- 快速连续切换时，旧请求取消，旧响应不能覆盖新状态。

## 6. 高级动效清单

### 6.1 导航

- 侧边栏选中底色使用共享布局动画在菜单项间移动。
- 移动端横向导航保留同样的选中轨迹。
- 侧边栏折叠使用短时长宽度过渡，内部文字不做逐字动画。

### 6.2 页面层级

- 页面标题、筛选工具栏、KPI、主内容区按层级错峰入场。
- 最大层级为四层，间隔约 35–55ms。
- 页面首次进入使用错峰；筛选和分页更新不使用整页错峰，避免频繁闪烁。

### 6.3 KPI 与数据

- KPI 数字从旧值递增到新值，时长约 420ms。
- 金额、进度和计数使用等宽数字，动画过程中不改变容器宽度。
- 第一次展示时从 0 递增；后续刷新从当前显示值递增。
- reduced-motion 下直接更新最终值。

### 6.4 Tab 与局部视图

- 详情页 Tab 下划线使用共享布局动画。
- Tab 内容约 160ms 淡入并上移 3px。
- 不强制显示 450ms 活动状态；业务请求自身仍可触发局部更新反馈。

### 6.5 弹层

- Dialog 使用约 180ms 的淡入和轻微缩放。
- Drawer 使用约 180ms 的侧向滑入。
- 关闭动画结束后再释放焦点并恢复滚动，保留现有 Esc、焦点锁定、遮罩和脏数据确认。
- Confirm 的按钮忙碌态与全局活动状态同步。

### 6.6 图表

- 首次加载使用 Recharts 原生动画，时长约 500ms。
- 数据更新使用约 300ms 动画。
- 趋势图与占比图错峰开始，不对图表容器做循环呼吸动画。
- reduced-motion 下关闭 Recharts 动画。

### 6.7 Toast、通知和错误

- Toast 保持右上角方向，使用约 180ms 的淡入和 6px 位移。
- 通知面板与 Toast 使用相同方向语言。
- 错误提示不做弹跳，只在结束后清晰出现。

## 7. 动效参数

统一动效参数写入 CSS 变量和 Motion token：

| 用途 | 统一时长 | 缓动或方式 |
|---|---:|---|
| 按钮与 hover | 140–160ms | ease-out |
| 页面进入 | 220ms | `cubic-bezier(.2,.72,.2,1)` |
| 页面退出 | 140ms | ease-in |
| Tab 内容 | 160ms | ease-out |
| 弹层 | 180ms | ease-out / 短弹簧 |
| KPI 数字 | 420ms | ease-out |
| 图表首次 | 500ms | ease-out |
| 图表更新 | 300ms | ease-out |
| Activity 最短可见 | 450ms | 管理器控制，不是 CSS 动画时长 |

动效只使用 `transform`、`opacity` 和必要的尺寸变化。不得对大型表格逐行动画，不得在大面积元素上使用高成本模糊或持续滤镜。

## 8. 无障碍与降级

- 遵循 `prefers-reduced-motion`。
- reduced-motion 下关闭页面位移、共享布局滑动、数字递增、图表动画和弹层缩放。
- ActivityBar 仍显示，但改为低动态的静态进度反馈。
- `aria-busy`、`role="status"`、`role="progressbar"` 和现有 `sr-only` 文案继续保留。
- 动画不改变键盘焦点顺序、不拦截 Esc、不延迟焦点恢复。
- Toast 文案仍是唯一明确结果来源，不要求用户从动画推断成功或失败。

- `CountUp`：只负责可访问的数字动画。
- `MotionTabs`：只负责 Tab 指示器和内容切换。
- 业务页面：声明活动和动画区域，不保存全局动画状态。

## 10. 测试与验收

### 10.1 构建

- `npm run build` 通过。
- 不新增 TypeScript 错误、Next.js 构建错误或 hydration 警告。
- `package-lock.json` 与新增依赖保持一致。

### 10.2 加载行为

- 正常快速响应时，加载状态可见约 450ms，而不是一闪而过。
- 慢请求时加载状态持续到请求完成，不提前消失。
- 请求失败时活动结束并显示错误，不出现永久进度条。
- 快速连续筛选或切页时，只保留当前页面的加载状态，旧响应不影响新页面。
- 并发活动全部结束后进度条才关闭。

### 10.3 业务回归

- 导航、筛选、分页、刷新、保存、审批、删除和导出行为不变。
- URL 状态、深链定位、Toast、表单校验、焦点锁定和脏数据保护不回归。
- 普通 Tab 与弹窗打开不出现人为 450ms 等待。

### 10.4 视觉与性能

- 在桌面、iPad 竖屏/横屏和手机宽度验证，无文字遮挡、布局跳动或横向溢出。
- 大量数据列表切换时无逐行动画、明显掉帧或重复请求。
- 页面切换只使用短时位移和透明度变化，不引入大幅横滑。
- 截取页面切换和加载状态的桌面、移动端截图，作为视觉验收记录。

### 10.5 Reduced Motion

- 开启系统 reduced-motion 后，位移、共享布局滑动、数字递增、弹层缩放和图表动画关闭。
- ActivityBar、`aria-busy`、按钮忙碌态和结果 Toast 仍然清晰可感知。

## 11. 非目标

- 不修改 FastAPI 接口、数据库结构、权限模型或业务流程。
- 不引入 GSAP、Lottie、Three.js 或其他动画运行时。
- 不把整站改造成全屏加载遮罩。
- 不为普通 Tab、弹窗打开和表格行 hover 增加最短等待。
- 不对大表格逐行动画。
- 不做与加载反馈无关的视觉改版或组件重构。
