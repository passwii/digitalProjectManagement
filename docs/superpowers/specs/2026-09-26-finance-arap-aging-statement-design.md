# 中国财务场景：应收应付账龄与对账单设计

## 目标与约束

本阶段补齐应收账龄、客户/供应商对账单，并将新建账套币种限定为人民币 CNY。系统按中国企业会计和税务工作流提供记账、对账与风险分析；本阶段不引入多币种、汇率、调汇，也不把管理分析报表表述成税务申报表。

财政部《会计信息化工作规范》（财会〔2024〕11 号）要求会计软件支持符合国家统一会计制度的凭证、账簿和报表；《企业会计准则第22号——金融工具确认和计量》及财政部 2025 年年报通知要求应收款项减值基于预期信用损失。账龄只提供风险分析输入，不能直接按逾期档位自动计提坏账准备；损失准备模型、税务口径和税率需另行配置并由财税顾问确认。

- [财政部《会计信息化工作规范》通知](https://www.mof.gov.cn/jrttts/202408/t20240809_3941452.htm)
- [财政部 2025 年企业年报工作通知：预期信用损失](https://kjs.mof.gov.cn/gongzuotongzhi/202512/t20251224_3980024.htm)

## 账务计算口径

- 账龄与对账单只汇总当前状态为 `posted` 的原始应收/应付凭证与收付款凭证；草稿、待审核和作废凭证显示为待入账/不计入正式余额。
- 按会计凭证日期（`voucher_date`）计算账龄，并明确标签“按凭证日”；现有往来单无合同到期日，不能把凭证日账龄冒称逾期天数。
- 应收增加额来自已过账应收单，减少额来自其已过账收款分配；应付增加额来自已过账应付单，减少额来自其已过账付款分配。
- 对账单按客户或供应商、可选往来科目和日期区间生成期初余额、本期增加、本期减少、期末余额及逐笔凭证明细。只按凭证日期分期，金额以 Decimal 字符串返回。
- 过账的冲销凭证按其凭证日作为反向流水展示。收付款冲销已过账时使用现有 `release_voucher_id` 作为恢复应收/应付余额的凭据；未过账收付款和冲销草稿不影响正式对账余额。
- 当前模型没有独立过账时间及合同到期日，报表按凭证日期反映最终已过账账务；历史期间在后续补过账凭证时会随凭证日期更新。本阶段不宣称提供不可变历史快照。

## API 与界面

- 新建账套的 `BookIn.base_currency` 只接受 `CNY`（大小写输入统一成 CNY）；保留历史账套数据原值与兼容列，不新增多币种能力。
- 增加应收账龄接口；复用 0–30、31–60、61–90、90 天以上四档，按凭证日龄分组；应付账龄统一切换到已过账口径。
- 增加应收、应付对账单读取接口，按账套、主体、可选科目和日期范围过滤。只读接口沿用 `_book_header` 的账套成员权限。
- 应收应付页签同时显示应收和应付账龄摘要；为客户/供应商提供日期区间和科目筛选的对账单弹窗，显示余额汇总、凭证状态和本期明细。
- 界面明确提示账龄从凭证日开始，不代表合同逾期日；对账单为账务核对输出，不直接用于纳税申报或自动计提坏账。

## 暂不包含

- 手工指定/拆分核销、预收预付、坏账准备自动计提、合同到期日、发票/税务申报数据、汇率与多币种、不可变历史报表快照。
