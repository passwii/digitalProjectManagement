# 横屏平板适配设计

## 目标

在不重做手机端、桌面端和业务流程的前提下，为全站已登录业务页面补齐横屏平板的布局适配。重点保证页面在平板可用视口内有清楚的信息层级、可读的业务数据和可触达的主要操作；允许宽表格在自身容器内横向滚动，但不隐藏关键字段或操作。

## 当前项目背景

- 前端使用 Next.js App Router、React、TypeScript 和 CSS Modules；业务页由 `(dashboard)` 路由组承载，Spark 演示站使用独立 shell。
- 主业务 shell 在 `web/components/ui/Shell.module.css` 中按宽度切换：手机断点为 `767px`；`768–900px` 使用堆叠 shell 与横向导航；更宽视口使用侧边栏。另有 `901–1180px` 的紧凑规则。
- 手机端 PWA / MobileDock 已有独立设计，不属于本轮重做范围。
- 现有页面断点分布在全局样式、共享组件与页面 CSS Module 中；有的页面已含平板规则，但没有覆盖全站的统一平板专项验收清单。

## 范围与边界

### 目标视口

- 本轮专项适配范围：**1180–1366 CSS px**，以横屏平板为主。
- 最低目标视口：`1180×820`。
- 重点验证视口：`1180×820`、`1280×800`、`1366×900`。
- 使用 CSS 视口宽度和 CSS media queries 判断布局，不使用设备型号、User-Agent 或 JavaScript 设备检测。

### 邻接断点

- `≤767px`：保留现有手机 PWA、底部 Dock 和手机页面布局，不纳入本轮改造。
- `768–1179px`：保留当前行为，不作为本轮平板专项目标；必要时做边界回归检查，避免新规则影响既有布局。
- `≥1367px`：保留当前桌面布局；做宽屏回归抽查。
- 现有 `901–1180px` 与页面内其他断点需要在实施时检查优先级，避免规则重叠造成意外覆盖；不得借本轮顺手扩展为全尺寸断点重构。

### 页面范围

覆盖所有已登录业务工作面，包括：

- 工作台与仪表盘。
- 项目台账、项目详情、进度、支出、审批、商机和资产管理。
- 财务、支出报表、通讯录、友商管理和系统管理。
- 功能更新及 Spark 演示站。

登录与密码修改、后端 API、权限模型、数据口径、业务写入流程和 URL 状态均不在本轮功能修改范围。手机专属导航不变。

## 设计原则

1. **共享框架优先**：先检查主业务 shell、导航、页面容器与通用页面头部，再按页面类型归纳问题；只有共享规则不能解决时才增加页面局部规则。
2. **延续现有信息架构**：平板保留桌面侧边栏与顶栏，不引入平板专用 Dock 或新的导航模式。空间紧张时可使用现有的手动侧栏折叠能力。
3. **保留业务信息**：不因宽度不足而隐藏关键字段、行内操作、状态或权限相关入口。表格不能清楚容纳所有列时，在表格自身容器内横向滚动。
4. **触控与键鼠并重**：不依赖 hover 才能发现或触发操作；主要操作应有足够触控面积（目标约 `44×44px`），同时保留键盘焦点、鼠标交互与清楚的焦点状态。
5. **不破坏既有体验**：延续深浅主题、减少动效、对比度、滚动、弹层焦点与错误反馈约定，不更改业务逻辑。
6. **克制调整**：只针对真实的拥挤、遮挡、溢出或不可操作问题调整列数、间距、容器宽度及断点；不做无关重排或全站视觉翻新。

## 布局与组件策略

### 1. 主业务 shell 与导航

- 在目标视口核对侧栏宽度、品牌区、导航标签、顶栏通知与账号菜单，以及内容区的可用宽度。
- 保留侧栏导航；必要时在 `1180–1366px` 使用紧凑侧栏宽度和相应内容留白，使主内容区获得稳定空间。
- 检查手动折叠前后页面是否正确使用剩余宽度，不能出现固定宽度内容溢出或交互状态丢失。
- 断点规则集中且互不矛盾；新样式只影响目标视口，手机与宽桌面规则保持原有语义。

### 2. 工作台与数据看板

- 依据可用宽度重排 KPI、图表、摘要和动态区；如果多列布局导致卡片过窄，则减少同排列数并维持清楚的层级。
- 数值、单位、图例、标题与状态不重叠；图表容器在重排后仍有合理可读面积。
- 保留当前数据加载、刷新、空态、错误态、筛选和路由行为。

### 3. 列表、表格与筛选

- 覆盖项目、进度、支出、审批、商机、资产、通讯录、友商、财务、报表及管理页面中的列表和表格。
- 检查页面标题、筛选、批量/新增操作、分页与表格主体之间的排列；允许工具栏自然换行，不得压住主要操作或制造页面级横向滚动。
- 可收紧非关键留白与列间距，但应保留字段辨识度、数值对齐、状态标签和操作区可用性。
- 宽表格仅在其自身滚动容器中横向滚动，表头、列和操作不被裁切到无法理解；不以隐藏业务字段作为适配手段。
- 保留现有列表/卡片呈现方式，本轮不将平板列表普遍改成卡片流。

### 4. 详情、表单、Dialog 与 Drawer

- 检查双栏表单、详情分区、标签栏、日期/选择控件、文件列表和按钮组在目标视口的最小可用宽度。
- 只有在字段列明显受压时才调整表单列数或局部排列；保留字段顺序、校验、保存与取消行为。
- 弹层宽度应适合平板视口并保留边缘留白；长内容在弹层内部滚动，关闭、焦点回收和键盘行为沿用共享组件约定。
- 不另起一套平板专属弹层实现。

### 5. 高密度模块与 Spark

- 财务、报表、系统管理优先核对宽表、数值列、分区导航、批量操作和筛选布局。
- Spark 使用其独立 shell 和页面样式单独走查；仅补充在目标视口可复现的布局问题，不将主业务 shell 规则强行套用到 Spark。

## 主要验收标准

### 目标尺寸验收

在 `1180×820`、`1280×800`、`1366×900` 检查上述所有页面范围，并满足：

- 页面本身无意外横向溢出；若存在宽表格，横向滚动仅发生在表格容器中。
- 侧栏、顶栏、页面标题、筛选和主要操作不被遮挡、不重叠，且可见可达。
- 表格字段、数值、状态及行内操作可辨识；没有为适配而隐藏的关键业务信息。
- 工作台卡片、图表和 KPI 不拥挤或互相覆盖；详情、表单与弹层可读可操作。
- 触控操作不要求 hover，键盘焦点清楚可见；深浅主题和减少动效模式可用。
- 业务路由、权限表现、URL 筛选状态和写入流程保持不变。

### 回归检查

- 在 `390px` 手机宽度及 `1440px` 桌面宽度抽查代表性页面，确认本轮规则没有改变既有 PWA / Dock 和桌面布局。
- 在 `1179px`、`1367px` 做断点邻接回归，确认目标 media query 不泄漏到范围外。这是边界回归，不扩展为窄窗口专项适配。
- 运行相关前端测试与生产构建；浏览器人工走查所有目标路由的布局，尤其是宽表格、弹层、筛选换行和主题表现。

## 实施分组建议

1. 盘点页面和现有 CSS 断点，整理目标路由清单与可复现的问题；建立目标宽度的基线截图/记录。
2. 收敛主业务 shell 的平板侧栏、顶栏与内容区宽度规则，确认断点边界。
3. 按类型调整工作台、共享页面头部/工具栏、表格与弹层的共用样式。
4. 按模块走查财务、报表、管理、其他业务路由及 Spark；只为已确认问题添加局部规则。
5. 完成目标视口、手机/桌面回归、自动化测试和生产构建，记录人工验收结果。

## 备选方案与取舍

- **共享框架优先 + 页面类型走查（采用）**：先处理 shell 和共用模式，再修有真实问题的页面；统一性与回归风险较平衡。
- **逐页打补丁**：初期简单，但同类工具栏、表格和弹层容易各自形成不同规则，后续难以维护。
- **全站一次性重排**：理论覆盖最全，但变更面与回归成本偏大，超出本轮“补齐横屏平板适配”的目标。
