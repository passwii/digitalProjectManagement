# 手机端（PWA）导航与信息架构设计

日期：2026-09-18
状态：待验收（第 1 轮方案 + 本地 HTML 原型）
原型：`docs/prototypes/blf-1127-mobile-pwa/index.html`（浏览器直接打开）
自检：`python3 docs/prototypes/blf-1127-mobile-pwa/verify.py`（50 项断言 + 截图）

## 1. 本轮目标与边界

只解决手机端的「壳与导航」，不动业务流程、接口、权限模型和 URL 状态契约：

1. 登录页在手机端**真正垂直居中**，不再是「上面大片留白 / 标题，表单挤到下面」。
2. 业务模块导航从顶部 sidebar 改为**底部 Dock**。
3. Dock 选中后以**卡片 / 抽屉**的形态展开，而不是直接整页跳走。

本轮**不做**：离线写缓存、推送通知、原生壳打包、后端任何改动。

## 2. 现状与问题

| 现状 | 问题 |
| --- | --- |
| `web/app/login/login.module.css` 的 `@media (max-width: 980px)` 只把 1.15fr/0.85fr 两栏压成一栏 | 手机端仍是桌面 story 的竖排：深色大标题 + 01/02/03 卖点占掉半屏，表单被推到下方，需要抬手甚至滚动 |
| `Shell.module.css` 在 `max-width: 900px` 把侧栏改成横向滚动条 | 导航仍是「顶部横向滚动」，标签一多就要横滑；8 个入口在 390px 宽度下不可读 |
| 全局只有 `max-width: 900 / 640 / 520 / 520px` 的宽度断点 | 属于**窄屏适配**，没有手机端专属布局（安全区、软键盘、触控尺寸、PWA 外壳） |
| 项目台账 / 审批中心是 `table.grid`，靠横向滚动兜 | 手机上操作列被挤出屏幕，行内按钮 26–30px，误点率高 |

## 3. 信息架构：8 个桌面入口 → 5 个 Dock 位

桌面侧栏当前由 `/meta/me/menus` 返回（非管理员 4 项 + 工作台；管理员额外 3 项）。
手机 Dock 上限 5 位，按**业务对象**而非页面分组：

| Dock 位 | 吸收的桌面入口 | 选中后的展开形态 | 默认档位 |
| --- | --- | --- | --- |
| 工作台 | 工作台 | 快捷跳转卡（待办 / 今日待填报 / 逾期 / 临近里程碑 / 本月支出） | peek |
| 项目 | 项目台账（含项目详情） | 状态筛选 chips + 最近项目卡 | peek |
| 进度 | 进度跟踪 | 待填报 / 逾期 / 临近里程碑预览卡 + 待处理条目 | peek |
| 费用 | 支出记录 + 支出报表 | 本月支出口径卡 + 「支出记录」「支出报表」两张模块卡 | peek |
| 我的 | 通讯录 / 审批中心 / 系统管理 / 账号 | 账号卡 + 管理与审批入口（仅管理员）+ 账号操作 | half |

### 3.1 为什么「费用」合并两条菜单

「支出记录」是录入面，「支出报表」是同一业务对象的汇总面。手机上并排两个 Dock 位会强制用户每次先自问「我要的是记录还是报表」；合并后报表作为抽屉里的第二张卡进入，Dock 位只占 1 格。

### 3.2 权限语义不变

`/meta/me/menus` 仍是**唯一入口**，手机端不新增角色判断：

- 非管理员：Dock 与「我的」抽屉中都不出现审批中心 / 系统管理 / 通讯录，不展示必然 403 的按钮；
- 管理员：三个入口出现在「我的」抽屉，并在「我的」Dock 位上显示待办红点；
- 权限同步失败：沿用现有降级策略（只保留参与性入口 + 可重试提示），不猜测管理员身份。

> 原型里用「管理员视角」开关演示两种菜单集合，对应同一份契约。

## 4. 展开形态：三态抽屉 + 卡片

同一张底部面板按停靠位分三档，手势语义与 iOS 地图 / Safari 一致：

| 档位 | 高度 | 遮罩 | 内容 | 用途 |
| --- | --- | --- | --- | --- |
| peek | 自适应（≤ 236px） | 无 | 2–4 张预览卡 | 选中 Dock 的默认档：不打断当前页，一眼看清「有什么、要不要进去」 |
| half | 56% | 有 | 卡片列表 + 筛选 | 需要比较几条记录时 |
| full | 整屏（保留状态栏 50px） | 有 | 列表 + 分页 | 筛选 / 详情必须全屏时 |

交互约定：

- 点 Dock → 进 peek（**不跳页**）；
- 再点当前 Dock → peek 收起；half/full → 降回 peek（保证不存在「点了没反应」的死键）；
- 上拖升档（peek → half → full），下甩 96px 以上降档 / 关闭；
- 点遮罩关闭；点卡片进入模块或详情；
- 抽屉内列表滚动到顶部时才允许整体拖拽，避免抢走列表滚动。

### 4.1 为什么是「抽屉里放卡片」

1. **抽屉**解决纵向层级（快捷面板与当前页共存）；**卡片**解决横向信息密度（每张卡就是一条业务结论）。
2. peek 不加遮罩、不遮内容，支持「看两眼就走」——这是手机端最高频诉求。
3. 升档复用现有 `components/ui/Modal.tsx` 的 Drawer 焦点管理与 Esc 逻辑，不需要第二套弹层组件。

### 4.2 表格 → 卡片

列表页（项目台账、审批中心）在手机端改为卡片流：一屏 2–3 条可读结论（名称 / 编号 / 状态 / 进度条 / 负责人 / 预算或执行率）。桌面端表格保持不变。

## 5. 登录页

1. 手机端保留品牌资产（`--navy-deep` 底色、网格纹理、SHZK 印章、字标、slogan），但删掉桌面的大标题与 01/02/03 卖点行。
2. 居中基准是**「品牌块 + 表单卡」整组**的中点；底部提示行用 `position: absolute` 脱离文档流，否则会把整组往上顶，表单就不在屏幕中心。
3. 输入框 46px 高、**字号 16px**——iOS Safari 在 `<16px` 的输入框聚焦时会自动放大整页，是手机端「页面莫名变大」的常见来源。
4. 软键盘抬起时表单上移、品牌块让位，主按钮与错误提示始终可见；密码框回车直接提交。
5. 校验逻辑与桌面完全一致（11 位手机号、密码非空、401 文案「手机号或密码错误」），不重写业务规则。

## 6. PWA 外壳：必须一起处理的 6 件事

| 项 | 做法 | 不做的后果 |
| --- | --- | --- |
| manifest + icons | 新增 `web/app/manifest.ts`：`display: standalone`、`theme_color: #0F2742`、`background_color`、192/512 图标（含 maskable）、`shortcuts` 指向工作台 / 待审批 | 装到桌面仍是浏览器窗口，地址栏占 ~60px |
| safe-area | Dock 与底部操作条 `padding-bottom: env(safe-area-inset-bottom)`；顶部用 `env(safe-area-inset-top)` | iPhone 上 Dock 被 Home 指示条压住 / 被刘海遮挡 |
| viewport | `viewport-fit=cover` + 交互元素回避边缘 8px | 圆角屏 / 横屏黑边与误触 |
| overscroll | `overscroll-behavior-y: contain` + 自建下拉刷新（原型已实现） | standalone 下整页橡皮筋、误触刷新丢状态 |
| 点击延迟 | `touch-action: manipulation`，所有可点元素 ≥ 44px | 双击缩放误触、行内小按钮点不中 |
| 离线兜底 | **首版不做**离线写缓存，只保证断网有明确错误与重试（复用 `LoadFailed`） | 乐观写离线会产生与审批 / 预算口径冲突的脏数据 |

## 7. 令牌与实现映射

原型里的手机端专用令牌（建议评审后并入 `globals.css`）：

```css
--m-dock-h: 58px;          /* Dock 内容高度（不含安全区） */
--m-appbar-h: 52px;
--m-sheet-r: 18px;         /* 抽屉顶部圆角 */
--m-tap: 44px;             /* 最小触控目标 */
--m-safe-b: env(safe-area-inset-bottom, 0px);
```

| 原型 | 落地位置 |
| --- | --- |
| Dock 组件 | 新增 `web/components/mobile/MobileDock.tsx` + `.module.css` |
| 三态抽屉 | 新增 `web/components/mobile/BottomSheet.tsx`（复用 `lib/modalFocus.ts`） |
| 登录页手机分支 | `web/app/login/login.module.css` 增加 `@media (max-width: 767px)`，页面结构不变 |
| 手机壳切换 | `app/(dashboard)/layout.tsx` 按 `matchMedia("(max-width: 767px)")` 或 CSS 断点二选一渲染 Dock / 侧栏，菜单数据仍取自 `useMenus()` |
| 列表卡片化 | 项目台账 / 审批中心增加卡片分支，桌面保留 `table.grid` |
| manifest | `web/app/manifest.ts` + `app/icon.svg` 扩成 192/512/maskable |

断点取 **767px**（而非现有的 900px）：900px 更多是平板 / 窄窗口，767px 才是手机。

## 8. 验收状态

`verify.py` 在无头 Chrome 中真实点一遍，50 项断言全部通过，覆盖：

- 登录页：卡片在框内、左右留白对称、整组垂直居中、输入框 ≥44px 且字号 ≥16px、首屏无滚动、提示行脱离文档流、键盘抬起后按钮仍可见、非法手机号被拦下；
- Dock：5 位且标签正确、贴底满宽、高度 = 58 + 22 安全区、触控 ≥44×44、内容底部留白足够、默认高亮、无横向溢出；
- 抽屉：peek 打开且 ≤240px 内、peek 无遮罩、首张卡片完整可见、上拖升档、遮罩可点、再点当前 Dock 降回 peek、peek 收起、全屏贴底且不遮状态栏；
- 详情：进入后隐藏 Dock、有底部操作条、返回后 Dock 恢复；
- 权限：普通用户看不到管理与审批入口，管理员视角出现审批中心 / 系统管理 + 待办红点；
- 费用抽屉含「支出记录 / 支出报表」与成本口径说明；
- 360px 窄屏：Dock 标签不溢出、无横向溢出、抽屉重新贴合底部；
- 最小字号 ≥10px；全程无 JS 报错。

## 9. 待你拍板的 4 个细节

- **Q1 Dock 第 4 位叫「费用」还是「支出」？** 原型用「费用」（含记录 + 报表）。若报表要单独立位，需砍掉「进度」或把「进度」并入「项目」抽屉。
- **Q2 peek 抽屉是「预览卡」还是「直接进模块」？** 原型默认 peek 不跳页；若改为点 Dock 直接跳页、长按才出抽屉，手势反了会影响第一周学习成本。
- **Q3 管理员入口放「我的」还是提升为第 6 个 Dock 位？** 原型放「我的」抽屉并按需显示 + 红点。
- **Q4 表格页是否改为卡片流？** 原型改为卡片流；若保留表格横向滚动，体验会明显差。
