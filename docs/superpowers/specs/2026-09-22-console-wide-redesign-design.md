# 全站交付控制台设计说明

## 目标

将数科云办公的已登录业务页面统一到 Login 与 Dashboard 已建立的「身份握手 · 交付链路」视觉世界，形成一套可持续扩展的全站控制台。用户在项目、进度、成本、审批、财务、报表、通讯录和系统管理之间切换时，应感到自己仍处在同一个可信、可追溯、持续推进的工作环境里。

## 已确认方向

用户确认采用「全站交付控制台」：深蓝操作环境、信号青链路、锁定酸橙动作、警示橙异常；直角控制台、细线分层、真实状态驱动的动效；保留现有 Table 与 Dialog/Drawer 编辑习惯，不改 API、认证、权限和数据语义。

## 成功标准

1. 所有已登录路由共享同一套背景、顶栏、侧栏、移动 Dock、按钮、输入、表格、Badge、分页、状态和弹层语言。
2. 页面首屏先回答“我在哪里、当前有什么、下一步做什么”，再展示低优先级明细。
3. 表格仍然承担高密度数据阅读，Dialog/Drawer 仍然承担编辑；改造不把熟悉的业务流程替换成装饰性卡片。
4. 动效只回应加载、刷新、筛选、状态更新、弹层进出和成功/失败反馈；`prefers-reduced-motion` 下内容和反馈仍然完整。
5. 390px 手机、平板窄屏和桌面宽屏都保持可操作；移动端 Dock、横向表格和全屏编辑弹层契约不回退。
6. 所有页面的空态、错误态、加载态和权限失败都提供中文、可恢复且不虚构数据的反馈。

## 视觉系统

### 颜色与层级

- 观测黑蓝 `#07131F`：页面背景。
- 控制台蓝黑 `#081622`：Shell、移动 Dock 和导航层。
- 控制台表面 `#0D1D2C`：表格、工具栏、Dialog、Drawer 和可操作区域。
- 信号青 `#6CF3FF`：焦点、链路、当前选中和数据线。
- 锁定酸橙 `#C6FF72`：主操作、完成和可执行状态。
- 中断橙 `#FF9A6A`：错误、逾期和需要介入的状态。
- 主文字 `#EAF9FB`，辅助文字使用带透明度的冷青灰。

强调色只承担状态和动作，不把每个区块染成彩色卡片；分层依靠实面、1px 边界和方向明确的阴影完成。

### 排版与形状

正文继续使用中文黑体栈，日期、编号、金额、状态码和技术标签使用等宽字体。页面 UI 采用固定字号阶梯，不使用过度流体的产品 UI 标题。输入、按钮、表格、卡片和弹层默认 0px 圆角；头像、状态点和移动抽屉保留必要的几何圆角。

### 共享结构

- `Shell`：深色侧栏 + 顶栏 + 面包屑 + 身份菜单 + ActivityBar + 移动 Dock。
- `PageHeader`：无白卡标题条，工具栏与主操作在同一条“命令带”中组织。
- `ListPageLayout` / `TableToolbar`：过滤、批量动作、通知和表格视口共享同一节奏。
- `table.grid`：深色高密度台账，表头为观测层，行 hover/定位使用细线信号，不使用厚重侧色条。
- `Modal` / `Drawer`：实面控制台，顶部状态线，底部操作带，移动端全屏或短确认居中。
- `PageState` / `Empty` / `Badge` / `ProgressBar`：共享“接入、校准、待检查、完成、阻断”状态词汇。

## 页面分组与处理

### 台账工作面

项目、商机、友商、通讯录保持 Table + Dialog/Drawer，升级筛选栏、列密度、行 hover、定位行和移动端卡片；编辑路径不改变。

### 交付与决策工作面

进度、成本、审批使用轨迹线、读数带、事项队列和状态节点突出下一步动作；表格仍作为明细事实层，不把审批和编辑流程强制改成看板。

### 财务与洞察工作面

报表和财务页使用读数带、期间状态和对账/核对语义，金额与日期保持等宽读数；图表、账簿表格和结账检查共享同一套状态颜色。

### 管理与系统工作面

系统管理、功能更新、修改密码、错误页和加载页使用同一套控制台反馈，不再出现与业务页脱节的浅色孤岛。

## 动效语法

- 页面切换：内容容器只做一次轻量 opacity/translate reveal，不做逐屏编舞。
- 筛选与刷新：保持表格骨架，ActivityBar 和局部状态线反馈“正在校准”。
- 表格：行 hover、定位和新增/更新只使用背景、边界和短距离 transform。
- Dialog/Drawer：150–220ms 的 opacity + translate/scale 进出，错误和成功使用状态线变化。
- 数据：金额/计数继续使用 CountUp，但不对静态说明做循环动画。
- 低动效：所有循环、延迟进入和 transform transition 在 `prefers-reduced-motion: reduce` 下关闭。

## 非目标

- 不修改后端接口、权限判断、认证会话、路由门禁、数据加载策略。
- 不删除 Table、Dialog、Drawer、移动 Dock 或项目编辑流程。
- 不新增没有真实数据来源的指标、客户数字、安全承诺或业务字段。
- 不把每个页面强行改成 Dashboard，也不引入需要额外依赖的动画库。

## 验证策略

- 先跑现有 unit 与 motion/DOM 测试，记录基线。
- 每一批改造后运行对应 DOM 测试与 TypeScript 检查。
- 最终运行全量测试、生产构建、`git diff --check` 和 Impeccable detector 一次。
- 通过本地前端与 API 服务验证登录、未登录重定向、核心路由响应和移动断点。
