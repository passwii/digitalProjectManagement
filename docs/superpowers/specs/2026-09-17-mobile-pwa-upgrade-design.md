# 手机端与 PWA 优化升级设计

> 状态：已确认  
> 日期：2026-09-17  
> 范围：现有 Next.js + FastAPI 项目管理系统的手机端完整适配、PWA 和最近页面只读离线

## 1. 背景

当前系统已经具备项目、进度、成本、审批、通知、报表和系统管理的完整业务闭环。现有前端在 `900px` 以下会把侧栏改为顶部横向导航，并允许宽表格横向滚动，但仍然是桌面界面的缩放版本，主要问题包括：

- 顶部品牌区、导航、搜索和账号区域占用过多首屏空间。
- 项目、进度、成本、审批和管理页面依赖桌面表格与横向滚动。
- 行操作依赖 hover，触屏上不易发现。
- 表单控件高度多为 `32px`，低于移动端常用触控目标。
- 登录和首次改密页共用桌面居中的 `360px` 卡片，没有针对手机键盘、安全区、输入缩放和密码管理器优化。
- 没有移动端专属信息架构、PWA、安全区和离线状态设计。
- 当前 token 同时存放于 `localStorage` 和可读 Cookie，不适合长期依赖。

本设计的目标不是简单增加媒体查询，而是建立一套手机端专属导航、卡片、抽屉、表单、复杂数据视图和 PWA 能力，同时保留桌面端现有高密度控制台体验。

## 2. 目标

### 2.1 核心目标

1. 手机端可以完成现有系统全部业务能力，包括项目、任务、里程碑、进度填报、预算、支出、审批、通知、报表和系统管理。
2. 手机端默认不使用横向滚动完成主要任务。高级表格可保留横向滚动，但必须是明确的次要入口。
3. 采用同一套 Next.js 代码库和域名交付响应式 Web + PWA。
4. 支持安装到主屏幕、独立启动、安全区适配、静态资源缓存和最近页面的只读离线访问。
5. 桌面端继续保留现有侧栏和表格布局，不因手机优化降低操作密度。
6. 权限、审批、数据口径和 API 契约保持单一来源，不为手机端复制业务规则。

### 2.2 成功标准

- 在 `375px`、`390px` 和 `412px` 宽度下，全部核心流程可完成。
- 触控按钮、输入控件和主要点击区域不小于 `44px`。
- 列表、详情、表单、审批、通知和成本流程不依赖 hover 或横向滚动。
- 普通 4G 和中端手机环境下，首屏 LCP `≤2.5s`、INP `≤200ms`、CLS `≤0.1`。
- PWA 可在 Safari 和 Android Chrome 中安装并独立启动。
- 断网时可查看最近打开的 10 个只读视图；所有写操作明确禁用且不进入离线队列。
- 退出登录、切换账号或权限变化后，用户隔离的离线缓存立即清除。
- 登录、首次改密和会话失效返回登录页时，手机端表单无需缩放、横向滚动或手动推动页面即可完成。
- 桌面端核心业务回归通过，不改变现有权限和审批边界。

## 3. 非目标

- 不开发独立移动 Web、原生 App 或微信小程序。
- 不针对微信或企业微信内置浏览器做专项兼容。
- 不实现完整离线编辑、写入队列或冲突合并。
- 不缓存当前账号的全部可见数据。
- 不重做桌面端视觉和表格结构。
- 不增加新的业务角色或放宽现有管理员审批边界。
- 不在本阶段引入评论、自定义字段、甘特拖拽或财务系统对接。

## 4. 已确认决策

| 决策项 | 结果 |
|---|---|
| 交付形态 | 同一套 Next.js 响应式 Web + PWA |
| 主要浏览器 | iPhone Safari 与 Android Chrome 最近两个大版本 |
| 导航模式 | 高频入口固定底部，管理与报表进入二级入口 |
| 首页方案 | 工作台优先，聚合 KPI、待办、风险和最近动态 |
| 列表与详情 | 卡片列表 + 底部抽屉 |
| 抽屉深度 | 半屏摘要，可展开到接近全屏 |
| “工作”入口 | 跨项目“我的工作”，聚合任务、填报、里程碑和跟进 |
| 复杂数据 | 默认指标、趋势、风险卡片和钻取；保留高级表格视图 |
| 离线范围 | 最近打开的页面只读离线 |
| 离线数据量 | 最近 10 个视图，保留 24 小时，总量不超过约 `5MB` |
| 离线写入 | 不支持，断网时所有写操作禁用 |
| 会话安全 | 迁移到 httpOnly Cookie、refresh 轮换和写操作 CSRF 防护 |

## 5. 响应式边界

### 5.1 手机

范围：`≤767px`。

- 使用移动壳、固定底部导航和单列内容。
- 列表中详情默认通过底部抽屉打开。
- 表单为单列布局，提交操作吸底。
- 登录和首次改密页使用独立的认证移动壳，不显示底部导航，并按键盘和地址栏变化动态调整高度。
- 图表和复杂内容占满内容宽度，不设置固定桌面最小宽度。

### 5.2 平板

范围：`768px - 1023px`。

- 继承手机卡片和抽屉组件。
- 可采用双列卡片和更宽的抽屉。
- 复杂报表可以使用简化表格。

### 5.3 桌面

范围：`≥1024px`。

- 继续使用现有侧栏、顶部栏、表格、Dialog 和 Drawer。
- 保持当前 URL、筛选、分页和业务行为。
- 手机组件不得影响桌面端 DOM 结构和操作效率。

### 5.4 布局约束

- 使用 `100dvh`、`env(safe-area-inset-*)` 和动态视口适配。
- 不按视口宽度缩放字号。
- 抽屉、底部导航和吸底操作必须处理 iOS 地址栏与键盘变化。
- 横屏时允许紧凑双栏内容，但不强制维持底部导航以外的固定高度。

## 6. 信息架构

### 6.1 底部导航

所有角色使用相同的五个一级入口：

1. **首页**：KPI、优先处理、风险和最近动态。
2. **项目**：项目卡片台账、搜索、筛选和项目抽屉。
3. **工作**：跨项目行动中心。
4. **成本**：跨项目预算、支出、调整和风险总览。
5. **更多**：审批、报表、系统管理、通知、账号和 PWA 安装。

角色权限只控制入口可见性和操作能力，不改变一级导航结构。

### 6.2 手机首页

首页从上到下依次为：

1. 问候和最重要的行动数量。
2. KPI：我的项目、逾期任务、待审批或待处理项。
3. “优先处理”：逾期任务、审批、预算风险和到期跟进。
4. 项目健康度摘要。
5. 最近动态。

点击“优先处理”项时，根据对象类型直接打开对应项目、任务、支出或审批抽屉。

### 6.3 项目

- 默认显示项目卡片，不显示桌面表格。
- 卡片包含名称、编号、状态、负责人、计划结束、进度和健康度。
- 筛选包括状态、负责人、部门、风险和最近关注。
- 点击卡片打开可展开的项目抽屉。
- 抽屉内部使用“档案 / 进度 / 成本 / 动态”四个页签。
- 深链进入 `/projects/{id}` 时，桌面显示现有详情页；手机打开项目列表并自动展开对应对象的全高抽屉，URL 中的项目 ID 始终是当前对象的唯一真源。

### 6.4 工作

“工作”是跨项目行动中心，分为：

- **待办**：今天到期、逾期、待提交和待确认。
- **我负责**：我负责的任务、里程碑和项目。
- **我参与**：我作为成员参与的项目行动项。

聚合内容：

- 任务和任务逾期。
- 进度填报和待确认填报。
- 里程碑临近和逾期。
- 跟进提醒。

每条记录必须显示所属项目，并支持直接打开对象抽屉完成操作。

### 6.5 成本

成本页默认显示：

- 总预算、已支出、余额和风险数量。
- 近 6 个月支出趋势。
- 按项目或科目的预算风险卡片。
- 支出、预算和调整记录入口。

点击风险卡片后打开钻取抽屉，显示预算、已支出、余额、执行率、相关支出和调整记录。

### 6.6 更多

“更多”页面包含：

- 审批中心。
- 报表。
- 系统管理，仅管理员可见。
- 通知与提醒。
- 账号和修改密码。
- PWA 安装说明。

管理员的高频待审批数量同时显示在首页和“更多”入口上。

### 6.7 登录与首次改密

登录和首次改密不放在业务移动壳内，使用独立认证移动壳：

- 首屏包含精简品牌、页面标题、必要说明和登录表单，不保留桌面卡片的固定宽度感。
- `375px` 宽度下只保留 `20px - 24px` 页面边距，表单占满可用宽度。
- 账号、密码和提交按钮高度不小于 `48px`，输入字号至少 `16px`，避免 iOS 聚焦输入框时自动缩放。
- 账号输入使用 `autoComplete="username"`，密码输入使用 `type="password"` 和对应自动完成语义，兼容 Safari、Chrome 与系统密码管理器。
- 密码框提供可控的显示或隐藏按钮；按钮具有 `aria-label`，且不改变输入焦点。
- 登录按钮在提交中保持固定尺寸并阻止重复提交。
- 首次改密页展示密码规则和字段级校验，三个密码字段保持单列。
- 键盘弹出时，当前输入框和错误信息必须保持在可视区域；登录按钮可随内容滚动，不遮挡最后一个字段。
- 支持安全区和 Home Indicator，横屏时表单可滚动但不裁切。
- 离线状态不能登录，页面明确提示需要联网；不提供离线登录或绕过会话校验。
- 会话失效跳回登录页时保留非敏感提示，例如“会话已过期，请重新登录”，但不回填账号之外的敏感信息。

## 7. 手机组件架构

### 7.1 移动壳

新增移动壳组件，负责：

- 底部导航。
- 安全区。
- 顶部页面标题和返回按钮。
- 全局离线状态。
- 内容滚动容器。
- 页面级 Toast 和错误边界。

桌面侧栏壳保持独立，二者共享菜单数据、权限查询和导航状态，不强行复用布局组件。

### 7.2 卡片列表

`MobileCardList` 负责：

- 统一卡片密度和间距。
- 标题、状态、负责人、日期、进度和风险槽位。
- 点击、长按和键盘操作。
- 加载骨架、空状态、错误和分页。
- 记录当前滚动位置，抽屉关闭后恢复。

### 7.3 可展开抽屉

`ExpandableDrawer` 基于现有 Dialog/Drawer 行为扩展，必须支持：

- 初始约 `48%` 高度。
- 向上拖动或点击展开按钮到约 `92%`。
- 展开后内部页签和独立滚动。
- 固定页头、返回、更多菜单和吸底主操作。
- 下滑关闭、返回键关闭、点击遮罩关闭。
- 脏数据确认和焦点恢复。
- 键盘弹出时自动调整可视区域。
- 不允许在抽屉内无限叠加新抽屉。

确认和短表单可以继续使用单层底部抽屉；长表单使用全高抽屉。

### 7.4 表单

表单规范：

- 单列为主，平板可双列。
- 标签位于输入框上方。
- 输入控件和按钮高度不小于 `44px`。
- 使用正确的 `inputMode`、`type` 和自动完成属性。
- 字段错误邻近显示，提交错误汇总显示。
- 提交时禁用重复操作并保持可恢复状态。
- 底部主操作吸底，兼容安全区和键盘。

### 7.5 高级表格

手机默认不渲染桌面宽表。报表和审计提供独立“高级表格”入口：

- 首列固定，横向滚动。
- 筛选项与桌面查询条件一致。
- 支持分页和导出。
- 页面外提供返回默认卡片视图的入口。

高级表格不是默认路径，不影响普通手机用户完成主要任务。

### 7.6 离线与安装

- `OfflineBanner` 显示在线、离线、缓存时间和缓存过期状态。
- `ReadonlyGuard` 在离线时禁用所有提交、审批、编辑和上传入口。
- `PwaInstallPrompt` 只在满足安装条件时展示，关闭后短期内不再主动弹出。
- 所有组件在 standalone 模式下仍适配安全区。

### 7.7 认证移动壳

`MobileAuthShell` 负责登录和首次改密，不依赖业务侧栏或底部导航，包含：

- 动态视口高度和安全区。
- 品牌与辅助说明区域。
- 单列表单和字段间距。
- 键盘可视区域处理。
- 密码显示或隐藏控件。
- 字段错误、接口错误和会话过期提示。
- 当前网络状态和离线不可登录提示。

桌面登录页可以继续复用现有居中卡片视觉，但表单语义、错误处理和会话逻辑与手机端保持同一实现。

## 8. 抽屉交互

### 8.1 半屏摘要

半屏抽屉显示：

- 对象名称、编号、状态和关键风险。
- 最重要的 3 至 5 个字段。
- 快捷操作。
- “查看完整详情”或展开入口。

### 8.2 全高详情

展开后显示：

- 项目：档案、进度、成本、动态。
- 任务：基本信息、填报历史、前置关系。
- 审批：申请内容、关联对象、审批意见和历史。
- 支出或预算：金额、状态、凭证、审批记录。

### 8.3 导航与状态

- 打开抽屉不创建不可恢复的历史堆栈。
- 浏览器返回键优先关闭抽屉，再返回列表。
- URL 保持对象或操作状态，便于刷新和分享。
- 关闭抽屉后恢复列表筛选、分页和滚动位置。
- 切换抽屉内部页签时保留当前对象和滚动位置。

## 9. PWA 设计

### 9.1 基础能力

- Web App Manifest。
- 标准图标、Maskable 图标和 `apple-touch-icon`。
- Standalone 启动模式。
- 主题色和背景色。
- Service Worker。
- 安装入口和已安装检测。
- 更新提示，避免用户长期运行旧版本。

### 9.2 静态资源缓存

缓存：

- Next.js 静态资源和字体。
- 应用壳。
- 离线占位页。
- 版本化图标和 Manifest。

不缓存：

- 登录和 refresh 响应。
- POST、PATCH、PUT、DELETE 请求。
- 上传文件和导出临时响应。
- 非允许列表的 API 响应。

### 9.3 最近页面只读缓存

离线缓存只包含最近成功打开的 10 个允许列表视图：

- 工作台摘要。
- 最近项目列表和项目详情。
- 我的工作。
- 成本总览。
- 通知。

缓存规则：

- 每个视图使用 URL、查询参数和用户 ID 作为缓存键。
- 保留 24 小时。
- 总大小不超过约 `5MB`。
- 只保存只读响应快照，不保存 token 和用户输入草稿。
- 新视图超过 10 个时淘汰最久未使用视图。
- 离线打开时显示缓存时间和“只读数据”标识。
- 超过 24 小时后只显示过期提示，不继续展示过期数据为实时数据。

### 9.4 用户隔离与清理

- 缓存命名空间包含当前用户 ID 或不可逆用户标识。
- 登录成功后初始化当前用户缓存。
- 退出登录、切换账号、密码变更或权限刷新失败时清除缓存。
- 应用收到会话失效响应时清除当前用户离线快照。
- Service Worker 更新不得跨用户复用缓存。

### 9.5 离线写操作

- 不将写请求加入后台队列。
- 断网时按钮明确禁用并说明需要联网。
- 网络恢复后不自动重放任何操作。
- 用户点击离线编辑入口时显示“联网后可继续”，不进入表单提交状态。

## 10. 会话与安全

手机端上线必须同步完成服务端会话改造：

- 登录成功后由服务端设置 `httpOnly`、`Secure`、`SameSite` Cookie。
- Access Cookie 保持短时效，refresh Cookie 只用于刷新。
- Refresh token 每次刷新后轮换，旧 token 进入黑名单。
- 所有写操作增加 CSRF 校验。
- 前端不再把 access/refresh token 写入 `localStorage`。
- 非 httpOnly 的用户标识 Cookie 只能保存非敏感展示信息。
- 登录限流同时按账号和 IP 组合控制。
- 离线缓存不包含 token、密码、审批意见草稿或附件内容。

开发环境允许在 HTTP 下使用非 Secure Cookie，但生产环境缺失 HTTPS、密钥或 Cookie 配置时拒绝启动。

## 11. 后端配套改动

手机端复用现有业务接口，不新增一套移动 API。需要补充：

1. Cookie 登录、刷新、退出和 CSRF 接口契约。
2. 会话状态在 Cookie 和 Bearer 兼容期内平滑迁移。
3. 对允许离线缓存的 GET 响应提供明确的缓存资格标识或响应头。
4. 登录、改密、退出和权限变化支持前端清理离线快照。
5. 附件与导出响应明确禁止 Service Worker 缓存。
6. 保留现有分页、软删除、权限和管理员审批边界。

离线数据仍来自现有业务查询，不建立第二套统计口径。

## 12. 前端改造边界

### 12.1 布局

- 将当前 Dashboard Layout 拆分为桌面壳与移动壳。
- 移动壳使用底部导航；桌面壳继续使用现有侧栏。
- 共用路由、菜单数据、权限查询和会话状态。

### 12.2 页面改造

- `/dashboard`：移动工作台。
- `/projects`：移动卡片列表。
- `/projects/{id}`：项目列表背景加对应对象的全高抽屉。
- `/progress`：跨项目“我的工作”。
- `/costs`：移动成本中心。
- `/approvals`：审批卡片和审批抽屉。
- `/reports`：指标卡片、钻取和高级表格。
- `/admin`：移动分组入口和管理抽屉。
- `/login`：认证移动壳、密码管理器兼容、输入缩放控制和键盘可视区域处理。
- `/change-password`：认证移动壳、字段级密码规则、键盘和错误位置处理。

### 12.3 状态

- 筛选、分页、当前项目、页签和视图模式继续写入 URL。
- 移动端扩展 `useUrlState` 到全部业务页。
- 抽屉开关使用可返回的 URL 状态，不创建不可恢复的本地状态堆栈。

### 12.4 代码组织

- 新增移动组件使用独立目录和样式模块。
- 页面文件过大时先提取数据 Hook、卡片和抽屉内容，再加入移动分支。
- 不在业务页面内复制桌面表格和移动卡片两套业务查询。

## 13. 加载、错误与空状态

- 首屏和列表使用与最终布局一致的骨架，避免布局跳动。
- 抽屉内容加载时保留标题和关闭入口。
- 保存失败保留表单内容并显示字段或全局错误。
- 离线且无缓存时显示明确离线空状态。
- 离线且有缓存时显示缓存来源和时间。
- 权限失效时退出离线快照并返回登录。
- 404、403 和会话失效使用不同状态，不统一显示为网络错误。

## 14. 可访问性与交互细节

- 主要触控目标不小于 `44px`。
- 使用语义化按钮、链接、表单和标题。
- 抽屉打开后锁定焦点并提供关闭路径。
- 关闭抽屉后焦点返回触发卡片。
- 所有图标按钮有可访问名称和 Tooltip 或 `aria-label`。
- 支持系统字号、减少动画和屏幕阅读器。
- 颜色不是状态的唯一表达方式。
- 不用 hover 作为唯一发现操作的方式。

## 15. 性能策略

- 列表继续使用服务端分页，不引入移动端全量加载。
- 图表按需加载，并在离开页面时销毁。
- 避免在手机上渲染隐藏的桌面宽表。
- 卡片列表使用稳定尺寸，避免文本和状态变化导致跳动。
- 图片、字体和图标使用缓存友好的响应头。
- Service Worker 不缓存大型导出和附件。
- 每次移动发布在真实设备和限速网络下测量 LCP、INP、CLS、请求数和缓存大小。

## 16. 测试策略

### 16.1 自动化

- 单元测试：离线缓存键、淘汰、过期和用户隔离。
- 组件测试：底部导航、卡片、抽屉拖动、返回键、脏数据确认和离线禁用。
- API 测试：Cookie 登录、refresh 轮换、CSRF、退出和权限边界。
- E2E：登录 → 首次改密 → 首页 → 项目 → 抽屉 → 任务填报 → 成本登记 → 审批 → 报表导出。
- PWA：Manifest、Service Worker、安装条件、离线启动和版本更新。
- 视觉回归：登录、首次改密、首页、项目列表、项目抽屉、工作、成本、报表。

### 16.2 设备与网络

- iPhone Safari：`375px`、`390px`。
- Android Chrome：`412px`。
- 正常网络、慢速 4G、完全离线、网络恢复。
- 登录聚焦账号和密码、键盘弹出、密码管理器自动填充、错误出现后的可视区域。
- 键盘弹出、横屏、系统大字号、减少动画。
- PWA 已安装和普通浏览器两种模式。

### 16.3 核心回归

- 管理员全局权限和普通用户项目边界不变。
- 审批入口和 `can_decide` 判定不变。
- 软删除项目不出现在离线缓存和正常列表。
- 报表、页面和导出使用同一统计口径。
- 退出登录后无法通过浏览器返回或离线缓存查看上一账号数据。

## 17. 分阶段实施

### Stage 1：移动壳与 PWA 基础

- 拆分桌面壳和移动壳。

### Stage 2：首页、项目和工作

- 移动首页。
- 项目卡片、筛选和可展开项目抽屉。

### Stage 3：成本、审批和全部表单

- 成本总览和钻取。
- 审批卡片和审批抽屉。

### Stage 4：报表、管理和高级表格

## 18. 风险与缓解

| 风险 | 缓解方式 |
|---|---|
| httpOnly Cookie 改造影响桌面和开发环境 | 保留有限的 Bearer 兼容期，先统一登录壳和测试，再移除旧存储 |
| 可展开抽屉手势复杂 | 统一实现和测试，不在业务页面各自处理拖动 |
| 离线缓存泄露历史账号数据 | 按用户命名空间、退出即清、单账号最多 10 个视图，绝不缓存 token |
| Safari PWA 行为与 Chrome 不一致 | 在真实 Safari 上验证安装、更新、缓存和安全区 |
| 移动端登录输入触发自动缩放或键盘遮挡 | 输入字号至少 `16px`、使用动态视口、聚焦滚动和真实设备键盘测试 |
| 手机与桌面组件重复导致维护成本增加 | 共享数据 Hook、查询参数和权限逻辑，仅拆分展示组件 |
| 大型页面改造引入回归 | 每个 Stage 独立验收，先提取稳定子组件，再切换移动展示 |
| 管理员全局数据无法离线完整覆盖 | 离线只缓存最近访问页面，不承诺全量数据可用 |

## 19. 最终验收

满足以下条件视为本轮手机端与 PWA 升级完成：

1. 五个底部入口和全部二级能力在手机可用。
2. 登录和首次改密在手机键盘、安全区、密码管理器和离线提示下可完整使用。
3. 核心流程不依赖横向表格、hover 或多层嵌套抽屉。
4. 项目、工作、成本、审批和管理页面均符合统一卡片与抽屉规范。
5. PWA 可安装、可更新，静态壳可离线打开。
6. 最近 10 个允许视图可只读离线查看，24 小时过期，退出即清。
7. 离线状态无法提交、审批、编辑、上传或自动重放写操作。
8. Safari 和 Android Chrome 目标尺寸、键盘、横屏、安全区和减少动画通过。
9. 性能指标达到目标，桌面端业务和权限回归通过。
10. 会话不再依赖 `localStorage` 保存 token，CSRF、refresh 轮换和限流生效。
11. 自动化测试、移动 E2E、离线测试、PWA 测试和核心权限测试全部通过。
