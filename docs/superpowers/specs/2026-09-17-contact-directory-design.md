# 通讯录花名册设计

## 目标

新增管理员专用的「通讯录」模块。通讯录是人员主数据，人员可以没有系统登录账号；如需要登录系统，可再关联一个现有账号。每位人员可上传身份证、学历、学位、专业证书、劳动合同及其他扫描件。

## 权限

- 菜单、列表、档案读写、附件上传与下载均仅对 `admin` 开放。
- 非管理员访问 `/contacts` API 一律在业务读写之前返回 `403`。
- 姓名、联系电话和部门以 `contact_profiles` 为准；关联系统账号后，姓名和部门同步到账号，避免两套主数据漂移。

## 数据模型

扩展 `contact_profiles` 为独立人员主表：

- 基础：姓名、联系电话、部门、工号、岗位
- 账号：`user_id` 可选唯一外键，允许为空；无账号人员不受影响
- 关联：`manager_id` 指向另一位通讯录人员、`updated_by` 指向操作账号
- 任职：工号、岗位、直属上级、用工类型、任职状态、入职/转正/离职日期
- 联系：工作邮箱、办公电话、办公地点
- 合同：合同类型、合同开始/结束日期
- 身份：性别、出生日期、身份证号、籍贯、政治面貌、婚姻状况、现住址
- 教育：最高学历、院校、专业、毕业日期、学位
- 应急：紧急联系人、关系、电话
- 其他：备注、创建/更新时间

附件继续复用 `attachments`，使用 `ref_type="contact"`、`ref_id=contact_id`，`project_id` 留空。附件分类固定为：

- `id_card` 身份证
- `education` 学历证书
- `degree` 学位证书
- `professional_cert` 专业证书
- `labor_contract` 劳动合同
- `other` 其他

单文件上限 20MB，支持 PDF、Word、Excel、PNG、JPG/JPEG。磁盘文件名使用随机前缀，下载时仍返回原始文件名。

## API

- `GET /contacts`：管理员分页人员列表，支持关键词、部门、任职状态筛选和白名单排序。
- `POST /contacts`：新建无账号或有账号人员。
- `GET /contacts/{cid}`：人员详情，同时返回关联账号和附件数量。
- `PATCH /contacts/{cid}`：部分更新人员；可选关联、切换或解除登录账号。
- `GET /contacts/options`：直属上级选择器。
- `GET /contacts/{cid}/attachments?category=`：附件列表。
- `POST /contacts/{cid}/attachments`：上传附件。
- `GET /contacts/{cid}/attachments/{aid}/download`：下载附件并写审计。
- `DELETE /contacts/{cid}/attachments/{aid}`：删除数据库记录和磁盘文件并写审计。

## 校验

- 工号非空时全系统唯一，空值按未填写处理。
- 任职状态仅允许 `active/probation/leave`。
- 用工类型仅允许正式、试用、实习、劳务、兼职、返聘。
- 合同类型仅允许劳动合同、劳务合同、实习协议、顾问协议、其他。
- 日期顺序必须成立：出生日期不晚于今天，入职不晚于转正，转正不晚于离职，合同开始不晚于结束。
- 身份证号允许 15 位或 18 位中国居民身份证格式。
- 直属上级必须存在且不能是本人。

## 页面

新增管理员菜单「通讯录」，页面保持现有商务蓝控制台风格：

- 顶部说明、关键词/部门/任职状态筛选。
- 提供「新建人员」按钮，无系统账号也可直接建档。
- 列表展示姓名、联系电话、工号、部门、岗位、用工类型、任职状态、入职日期、附件数、账号状态。
- 点击行打开右侧宽抽屉录入档案，按基础身份、任职合同、教育经历、紧急联系人分组；登录账号是可选字段。
- 抽屉底部提供附件分类选择、上传、下载和删除；保存档案不会丢失已上传附件。
- 已有系统账号自动保留在通讯录中；新系统账号创建后自动生成关联人员。

## 测试

- 非管理员列表、详情、写入、附件接口稳定 `403`。
- 管理员可不创建账号直接新建人员。
- 管理员可将人员关联到现有账号，且同一账号只能关联一位人员。
- 工号唯一，人员档案可增量更新。
- 附件上传、列表、下载、删除全链路，拒绝类型和分类外输入。
- 菜单只对管理员返回通讯录入口。
- 前端 `npm run build` 通过。
