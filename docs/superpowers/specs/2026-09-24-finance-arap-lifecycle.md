# 财务核销释放与账套回收站设计

## 目标

补全 FIFO 收付款核销从预占余额到撤销预占的生命周期，并提供可恢复的账套软删除。账套底层数据在移入回收站后继续保留；只有系统管理员可以删除、查看回收站和恢复。

## 业务规则

### 收付款核销

- 创建收款/付款时仍立即增加目标往来单的 `applied_amount`，分配明细进入活动状态。
- 活动分配通过 `released_at IS NULL` 判定。释放时只写释放时间、操作人、原因及可选的冲销凭证 ID，不删除分配历史。
- 草稿凭证删除、草稿/待审核凭证作废时，释放它作为来源的活动分配并同步扣减目标单据的已核销金额；作废需要保留原因。
- 正常过账保留核销。冲销凭证只有在实际过账时才释放原凭证的分配；仅创建冲销草稿不会更改未核销余额。
- 编辑带活动核销分配的收付款凭证被拒绝。冲销凭证不能再次冲销，同一原凭证不能重复生成有效冲销单。
- FIFO 候选往来单按账套、类型、主体（及可选科目）筛选并加行锁，避免并发收付款超额核销。
- 迁移会将既有已作废、已删除来源凭证，以及已过账冲销凭证对应的分配标记为已释放，并将其金额从目标的 `applied_amount` 扣回；其余历史分配视为活动。

### 账套软删除

- `account_books.deleted_at` 和 `deleted_by` 标记回收状态；不删除账套或任何关联数据。
- 常规账套列表和所有账套访问入口排除回收站项目。回收站编码保持唯一，移入回收站的编码不能被新账套重用。
- 删除、回收站列表、恢复接口都要求系统管理员；删除还要求服务端验证账套编码及保留数据确认。
- 前端删除有三步：说明影响并确认、勾选了解保留/不可访问状态、输入完整账套编码后最终提交。取消操作不修改数据。
- 恢复清除软删除标记并恢复原账套与成员关系；审计日志记录删除、恢复、核销释放和冲销释放。

## 接口

- `DELETE /finance/books/{book_id}`，body：`{ "confirmation_code": string, "acknowledged_retention": true }`
- `GET /finance/books/recycle-bin/list`：管理员获取回收站账套及删除时间、操作人。
- `POST /finance/books/{book_id}/restore`：管理员恢复账套。

## 数据与事务

- 新迁移增加账套删除字段；应收应付分配增加 `released_at`、`released_by`、`release_reason`、`release_voucher_id`。
- 分配行、目标往来余额、凭证状态和审计日志在同一数据库事务中提交。
- 释放只处理未释放行；如目标余额不足以覆盖释放金额，事务失败并回滚，避免形成负数或静默不一致。

## 界面

- 管理员在财务工作台账套选择区可进入回收站，即使当前没有活动账套也可访问。
- 当前活动账套提供“移入回收站”入口；回收站展示账套编码、名称、删除时间并支持恢复。
- 账套被移入回收站后，工作台切换到其他活动账套；若无其他账套，显示空状态与新建入口。

## 不在本阶段

- 物理删除账套/凭证数据。
- 允许普通成员查看或恢复回收站数据。
- 手工修改 FIFO 分配金额或释放单条分配。
