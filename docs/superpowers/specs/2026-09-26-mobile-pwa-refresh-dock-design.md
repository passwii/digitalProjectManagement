# 手机 PWA 下拉刷新与 Dock 入口面板设计

## 目标与边界

在继续逐页打磨前，让手机端刷新真正更新当前页面的数据，并让 Dock 的一次点按直接呈现可操作入口。保留五位 Dock、权限规则、现有深色控制台视觉语言与业务页面路由。刷新覆盖宽度不大于 767px 的全部路由，包括登录、密码修改、工作台和 Spark；Dock 仍只显示在手机工作台外壳。

本设计取代 `2026-09-18-mobile-pwa-navigation-design.md` 中 D2 及第 4 节的三档抽屉交互约定：不再使用 peek、half、full 或拖动换档。D1 的五位分组、D3 的权限过滤和各卡片的业务落点继续有效。

## Dock 交互

- 工作台、项目、进度、支出、我的仍占五个固定位置。点任一位，打开同一张单档入口面板；点当前位收起，点其他位直接切换内容。
- 面板最高约为可视高度的 78%，避开顶部安全区；底部为常驻 Dock 留出空间。只有卡片列表在面板内原生纵向滚动，面板本身不接受拖动。
- 打开时显示遮罩；点遮罩、明确的“关闭”按钮或按 Escape 均直接关闭。打开后焦点进入面板，关闭后回到触发的 Dock 位；减少动效设置下取消入退场动画。
- 头部展示分组名称、简短说明、关闭按钮和适用时的“进入模块”直达链接。数据加载或失败时，直达链接仍可使用。
- 内容统一使用全宽卡片行。项目的状态筛选、进度的待处理条目、支出的记录与报表入口、我的账号与权限入口继续使用原有数据和权限判定。卡片点按一次即进入落点，同时关闭面板。
- 保留当前路由高亮与待办角标。卡片和 Dock 的可点击区域至少 44×44px，面板内容可用键盘与读屏操作。

## 下拉刷新

- 根布局统一挂载手势与刷新协调器，登录、密码修改、工作台、Spark 及后续新增路由都使用同一入口。单指向下、方向明确且越过 56px 阈值后触发；页面及触点所在的全部纵向滚动容器都必须位于顶部。横向滑动、输入与编辑控件、弹层内手势均不触发。`touchcancel` 只复位，不发请求；刷新中不重复触发。
- 指示器使用中性的圆形转圈，不占内容流，停在手机顶栏下方，不使用业务品牌配色。松手后显示刷新状态；失败时给出简短原因和“重试”。刷新成功才增加成功次数。
- 刷新协调器只通知当前页面已注册的数据加载器，并等待其请求结束；10 秒仍未结束时取消本次请求，提示检查网络连接。共用 `useAsyncData` 的页面自动接入；工作台、审批、项目详情等自管理请求页面显式注册加载器。没有客户端数据加载器的页面刷新当前路由数据。请求失败保留当前页面的错误表达，并让指示器提供重试。
- 保留当前 URL、查询参数、筛选与标签状态，不通过整页重载或强制重挂载清除页面状态。项目详情存在未保存文档或正在提交操作时拒绝刷新，明确提示先完成编辑，以免服务端数据覆盖本地草稿。
- 手势只在手机宽度启用，桌面外壳不出现下拉刷新交互。手势捕获放在窗口捕获阶段，覆盖页面布局、Portal 和可滚动内容。

## 实施范围与验收

1. 建立页面刷新协调器，接入 `useAsyncData` 及自管理请求页面；修复旧实现仅调用 `router.refresh()`、失败也计为成功的问题。
2. 收敛 Dock 与 BottomSheet 为单档面板，移除拖动处理和预览档布局；保留五位内容、权限、路由和视觉令牌。
3. 检查 360px、390px、低高度视口、动态安全区、深浅主题、键盘操作和减少动效。验收以一次点按可见并可进入卡片、一次下拉确实重新取数、失败可重试、编辑中不丢草稿为准。
