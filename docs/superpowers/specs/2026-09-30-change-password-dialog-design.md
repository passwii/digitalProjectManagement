# 修改密码页面与弹窗设计说明

## 目标

修正 `/change-password` 将首次强制改密文案复用于普通改密的问题，并让用户从已登录工作台主动修改密码时继续停留在当前页面，以控制台 Dialog 呈现表单。

## 已确认方向

- 首次登录且服务端 `must_change_pwd` 为真时，保留独立的改密流程；标题和提示明确表达“首次登录 / 请先修改密码”。
- 普通用户从桌面账号菜单或移动端“我的”入口主动改密时，使用 Next.js 路由拦截展示 Dialog，关闭后返回原工作台页面。
- 普通改密文案使用通用“修改密码”，不再出现“首次登录”。
- 直接访问 `/change-password` 时根据当前用户的 `must_change_pwd` 选择首次或普通文案；首次流程不能被关闭或绕过。
- 保持现有密码校验、`authApi.changePassword` 请求及会话行为，不更改后端接口或认证规则。

## 交互与结构

为 `(dashboard)` 路由组增加并行 `@modal` 插槽和 `(.)change-password` 拦截路由。正常客户端导航由该拦截路由渲染共享改密表单的 Dialog；该插槽在直接访问时回退为空，原有顶层 `/change-password` 页面继续承担首次强制改密和直接访问场景。共享表单只维护一份字段状态、校验、提交与错误处理，场景通过明确的 `required` 属性驱动标题、说明、关闭动作和成功后的导航。

Dialog 复用现有 `components/ui/Modal` 行为，包括 Esc、遮罩、焦点管理、滚动锁定和移动端布局。普通改密可关闭；提交期间禁用关闭和重复提交。成功后显示现有的完成路径：普通改密关闭弹窗并留在原页面，强制改密跳转到工作台。

## 错误与边界

- 服务端密码错误和校验错误继续显示在表单内，不丢失当前输入。
- 未确认用户身份时不假定其为首次改密；页面待身份加载后再呈现场景文案。
- 强制改密仅能通过服务端 `must_change_pwd` 状态决定，不以路由来源或客户端传入参数作为权限依据。
- 移动端普通改密沿用拦截路由 Dialog 的全屏/适配行为；强制改密仍是独立全屏页。
