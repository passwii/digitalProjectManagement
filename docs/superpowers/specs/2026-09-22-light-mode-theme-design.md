# Light Mode 主题设计规格

## 目标

在现有“全站交付控制台”视觉系统上增加完整的 Light Mode，并通过顶栏用户菜单提供三档主题选择：浅色、深色、跟随系统。默认主题为深色，用户选择持久化到浏览器本地；不改变认证接口、业务数据、路由门禁、表格操作习惯和弹窗编辑方式。

## 设计方向

Light Mode 定义为“信号日光台”：保留当前产品的直角控制台、测量线、青色链路和酸橙执行色，但把深蓝黑工作面转化为冷白画布、浅蓝灰导航和白色内容表面。它不是通用白色 SaaS 皮肤，而是同一套交付控制台在明亮办公环境下的另一种工作状态。

### 视觉关系

| 角色 | 深色模式 | 浅色模式 | 规则 |
| --- | --- | --- | --- |
| 工作区画布 | `#07131F` | `#F3F7FA` | 页面最大面积，低纹理、低干扰 |
| 内容表面 | `#0D1D2C` | `#FFFFFF` | 卡片、表格、弹窗的实面层 |
| 次级表面 | `rgba(13,29,44,.72)` | `#EAF2F6` | 表头、工具栏、禁用态和导航层 |
| 主文字 | `#EAF9FB` | `#10263A` | 正文、标题、关键数据 |
| 次文字 | `rgba(201,227,235,.72)` | `#496779` | 辅助说明、表头与次级信息 |
| 弱文字 | `rgba(201,227,235,.48)` | `#607988` | 仅用于非关键标注，不承担唯一信息 |
| 链路信号 | `#6CF3FF` | `#006E86` | 链接、焦点、选中线与导航状态 |
| 执行动作 | `#C6FF72` | `#B8E86B` | 主按钮、已完成、可执行状态 |
| 警告 | `#FFC46B` | `#A85C00` | 保持语义，不只依赖颜色 |
| 错误 | `#FF9A6A` | `#C24735` | 保持语义，不只依赖颜色 |

浅色模式降低高饱和色大面积铺陈，青色主要用于路径和焦点，酸橙只用于行动与完成状态；边界、文字和图标必须保留形状或文案提示，不能让颜色成为唯一状态信号。

## 主题状态模型

### 模式定义

```ts
type ThemeMode = "light" | "dark" | "system";
type ResolvedTheme = "light" | "dark";
```

- 默认 `ThemeMode` 为 `dark`。
- `light` 解析为浅色，`dark` 解析为深色。
- `system` 读取 `prefers-color-scheme`，并监听系统变化。
- 本地存储键固定为 `shuzhi-theme-mode`；非法值、读取异常和无存储值都回退到 `dark`。
- 解析后的主题写入 `<html data-theme="light|dark">`，同时设置 `color-scheme`，让原生控件与滚动条遵循当前模式。
- 首屏通过 `beforeInteractive` 初始化脚本优先读取本地选择，避免浅色用户刷新时先闪现深色。
- Login 页面保留当前科幻深色视觉世界；工作台及其 Portal 弹窗、Drawer、Toast、移动 Dock 使用当前主题。

### 用户菜单交互

用户 hover 菜单在“功能更新”和“修改密码”之后增加“显示模式”分组。分组内有三个 `menuitemradio`：

- 浅色
- 深色
- 跟随系统

当前项显示选中标记和 `aria-checked="true"`。鼠标点击立即应用但不关闭菜单；键盘用户可在同一菜单中使用方向键、Home、End、Esc；移动端使用同一组 44px 最小触控目标。菜单外观仍与现有顶栏身份区一致，只增加轻量分组线和状态提示。

## 架构与文件边界

### 主题基础层

- 新增 `web/components/theme/theme.ts`：定义模式类型、存储键、合法值校验、系统主题解析等纯函数。
- 新增 `web/components/theme/ThemeProvider.tsx`：管理模式、系统媒体查询订阅、本地持久化和 `<html>` 属性同步；导出 `useTheme()`。
- 修改 `web/app/layout.tsx`：加载首屏主题初始化脚本，并在根布局中包裹 `ThemeProvider`。

### 菜单组件层

- 新增 `web/components/theme/ThemeModePicker.tsx` 与对应样式：只负责三档主题选择和可访问语义，不承担存储逻辑。
- 修改 `web/app/(dashboard)/layout.tsx`：在现有 UserMenu 中挂载主题选择器；将菜单键盘导航选择器扩展到 `menuitemradio`，保持现有 hover、focus、tap、Esc 和延时关闭行为。
- 不新增第二个账号入口，不改变退出登录、修改密码、功能更新的路径与行为。

### 样式与主题 token

- 修改 `web/app/globals.css`：建立全局深色默认 token 和 `:root[data-theme="light"]` 语义映射，覆盖画布、表面、文字、边界、交互、状态和阴影。
- 修改 `web/components/ui/Shell.module.css`：移除会覆盖 Light Mode 的深色硬编码，补充浅色导航、顶栏、身份区、菜单和侧栏状态；保持现有桌面宽度、窄屏断点和移动端结构。
- 对 Portal 挂载到 `body` 的 Dialog、Drawer、Toast、BottomSheet 只依赖全局 token，不做组件级重复主题分支。
- 表格继续保持当前密度、列宽和横向滚动行为；Light Mode 只改变表头、边界、行 hover、命中行和操作状态的视觉层。

## 动效与无障碍

- 主题切换使用短促的颜色/边界过渡，不重排页面、不闪烁内容、不播放装饰性全屏动画。
- 遵循现有 `prefers-reduced-motion`：关闭主题过渡和菜单入场动画，但保留状态与结构变化。
- 主题选择器使用真实按钮与 `menuitemradio` 语义，保留键盘焦点环、当前状态文本和可触控尺寸。
- 浅色和深色均验证正文、表头、按钮、焦点环、错误/警告、禁用态和 Portal 层的对比度；状态同时使用文字、图标、边界或位置表达。
