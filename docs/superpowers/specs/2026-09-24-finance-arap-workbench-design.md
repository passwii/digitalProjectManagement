# 财务往来工作台设计

## 现状与目标

财务后端已经支持应收、应付单据、按主体 FIFO 收款/付款核销（并可选按科目限定）、以及应付账龄汇总，但 `/finance` 工作台没有这些操作入口。账套已有客户、供应商和现金流辅助资料接口；往来记录保存的是对应账套内辅助资料的 ID。

本阶段为现有 API 补上可操作的财务工作台流程，不新增数据库迁移，不把项目台账客户或“我的友商”误作财务客户/供应商。

## 方案选择

1. **在财务工作台增加“应收应付”页签（推荐）**：沿用当前账套选择、会计期间、权限状态、表格和对话框，操作后可以继续去凭证页审核。用户始终留在同一账套上下文中。
2. 为应收与应付分别增加独立路由：职责边界更清楚，但会复制财务页导航、账套选择和加载处理，超出本阶段需要。
3. 只在现有凭证页增加单据入口：减少页签，但会把往来台账、核销和普通凭证混在同一视图，难以查看主体余额与账龄。

采用方案 1。

## 页面与交互

- 增加“应收应付”一级页签；页签内提供“应收”和“应付”分区，保留当前账套和开放期间。
- 两个分区显示往来主体、往来科目、日期、摘要、金额、已分配金额、可核销余额和关联凭证编号。主体名称通过账套内客户/供应商辅助资料映射；若历史记录找不到主体，显示其编号以便排查。
- 提供主体搜索、刷新、新建应收单和新建应付单。主体、科目、金额和日期均需校验；往来科目必须是启用的末级科目并启用对应客户/供应商辅助核算，另一方科目不能要求缺失的主体辅助项。
- 系统管理员可在该页维护客户、供应商和现金流项目辅助资料；其他财务角色只选择已维护的项目。辅助资料仍由后端权限控制。
- 有未核销余额的主体与科目组合可登记收款或付款。表单要求开放期间、日期、正数金额、启用的现金/银行末级科目和现金流项目；金额不得超过该主体、该往来科目合计可核销余额。后端按科目范围内的日期与单据 ID 自动 FIFO 分配，不提供人工指定分配。
- 应付分区读取后端账龄汇总，提供“截止日期”和 0–30、31–60、61–90、90 天以上金额。当前没有应收账龄接口，因此本阶段不显示应收账龄，避免把应付口径误用于应收。
- 新建应收/应付或登记收付款后刷新对应列表、账龄与余额。收付款成功提示包含生成的凭证编号，提示用户到凭证页继续审核和过账。

## 数据与权限

- `web/lib/api.ts` 仅补齐现有 API 的类型和调用：辅助资料列表/创建、应收/应付列表/创建、收款/付款、应付账龄。
- 所有财务请求继续发送 `X-Account-Book`，账套切换时旧请求由现有 `useAsyncData` 取消或重置。
- 创建往来单要求财务制单或主管角色；收付款要求出纳或财务主管；客户、供应商和现金流辅助资料新建入口只对系统管理员显示，真正鉴权继续由后端执行。
- 页面不直接修改凭证状态，不新增现金账或手工核销算法。操作结果以服务端返回和已有 API 错误码为准。

## 重要语义与范围

- 当前后端在登记收款/付款时立即写入 FIFO 分配并减少可核销余额，同时创建草稿凭证。因此界面必须明确标注“核销额已占用，凭证仍待审核/过账”，不得称作“已结清”。
- 当前后端没有与应收应付联动的撤销/释放分配操作。本页不提供撤销收付款入口；用户提交前需再次核对主体、期间和金额。若草稿凭证被其他途径作废或删除，分配释放需后端另行完善。
- 往来列表返回 `account_id`；FIFO 收付款接口接受可选 `account_id` 范围。新工作台总是传入所选往来科目，旧调用不传时仍保留原先按主体跨科目分配的行为。
- 本阶段不做应收账龄、人工分配、客户/供应商对账单、坏账、预收预付、税务发票、项目成本转会计凭证或财务角色管理页面。

## 完成标准

- 财务工作台在有财务权限时提供应收应付入口；账套和期间上下文传递正确。
- 使用辅助资料 ID 创建应收/应付，列表能显示可读主体名称和可核销余额。
- 收款/付款以选定主体与往来科目调用 FIFO API，金额超出该范围余额会显示后端错误；成功后列表及应付账龄刷新，并清楚提示草稿凭证待审核。
- 应付账龄截止日期可更改；加载、空状态、失败重试和辅助资料缺失均有明确反馈。
- 管理员可建立客户、供应商和现金流辅助资料；非管理员没有该写入口。
- 不新增后端迁移；静态检查通过。
