# 友商管理清理与合同附件上传设计

## 目标

精简友商管理：取消友商类型分类与筛选，移除友商档案中的友商类型和人员信息；保留友商基本信息、业绩合同和附件管理，并在添加业绩入口旁提供合同附件上传。

## 范围

- 友商列表只保留友商名称搜索框，搜索参数只匹配 `partners.name`。
- 友商列表移除类型筛选、类型列和人员数量列；保留删除操作。
- 友商档案移除友商类型字段和整块人员信息区域。
- 后端移除 `partner_type` 字段、`PartnerMember` 模型、人员 CRUD 接口及相关序列化字段。
- 新增数据库迁移，删除 `partners.partner_type` 列和 `partner_members` 表；降级迁移恢复结构但不恢复已删除数据。
- 在“添加业绩”按钮后增加“上传合同附件”按钮，使用现有上传队列和 R2 存储接口，固定附件分类为 `contract`。
- 合同附件沿用现有 PDF/图片在线预览、下载和删除能力；普通附件分类入口不再重复提供合同分类。

## 方案与数据流

采用全链路清理方案，而不是仅隐藏前端字段。这样可以防止旧字段继续从 API 返回，也避免人员信息接口与已删除的页面入口继续产生维护成本。

友商列表请求只发送 `keyword`、分页和排序参数，后端将 `keyword` 转换为友商名称的模糊匹配。友商详情只返回基本信息、业绩合同和附件，不再包含人员数组或人员数量。

合同附件按钮复用现有 `useUploadQueue`：选择文件后调用 `partnersApi.upload(partner.id, "contract", file, options)`，上传结果通过现有附件查询刷新；上传完成后仍由 `AttachmentPreviewDialog` 使用安全的下载地址预览 PDF 和图片。

## 错误处理

- 友商名称搜索、详情读取和保存沿用现有错误提示与加载状态。
- 合同附件上传沿用现有批量上传失败、重试和取消提示。
- 上传失败时不更新附件列表；成功后刷新服务端附件列表，避免前端状态与 R2 元数据不一致。
- 数据库迁移使用存在性检查，支持在已有部分迁移环境中安全执行。

## 测试策略

- 后端测试验证：友商创建和详情不再接受或返回已删除字段；名称搜索可命中；人员接口不可用；合同附件分类仍可上传。
- 前端源代码契约测试验证：列表无类型筛选和人员列，档案无类型/人员字段，合同上传按钮使用 `contract` 分类并复用现有上传接口。
- 运行后端友商测试、前端相关单元测试及 TypeScript 检查。

## 非目标

- 不改变友商模块的权限范围、删除操作、业绩合同字段或 R2 存储实现。
- 不迁移或恢复历史人员数据；数据库降级只恢复空结构。
