# Dashboard「交付坐标盘」重设计规格

## 目标

将 Dashboard 从“指标卡 + 图表 + 表格”的通用 SaaS 首页，重构为与 Login 页同源的「交付坐标盘」工作面：用户进入后能在一个首屏内判断项目态势、找到需要介入的事项，并继续进入项目、审批、进度和报表等业务路径。

本次只保留 Login 页已经成立的视觉世界，不修改 Login 页面本身，也不新增后端接口或虚构业务数据。

## 设计方向

### 视觉母体

- 深黑蓝作为工作环境，信号青表示链路、焦点和可观测状态，酸橙表示可执行或已锁定状态，中断橙表示风险与失败。
- 直角实面、1px 冷色边界和定向阴影组成结构；不使用白色圆角商业卡、玻璃拟态、泛用渐变或装饰性雷达/轨道扫描。
- 中文承担产品语义，等宽字体只承担编号、日期、百分比、金额和状态读数。
- 动效表达“接入、定位、介入、校准”，不制造虚假的同步率、性能指标或延迟。

### 首屏结构

1. **工作台接入头部**：主标题“交付坐标盘”，副文案解释项目状态、介入事项和资金脉冲的统一工作面；右侧保留刷新和管理员审批入口。
2. **状态读数带**：以一条横向基线承载我的项目、逾期任务、待审批/未读通知、本月支出四个读数。它们是可扫描的读数节点，不再是四张独立 KPI 卡。
3. **项目航迹区**：用项目航迹列表替代健康度表格。每一行展示项目名称/编号、状态、进度、预算执行率、逾期任务和计划结束时间；项目名称继续链接到详情页，所有字段来自 `DashboardSummary.health`。
4. **需要介入队列**：从 `Weekly` 的逾期、7 天内到期、最近填报以及 KPI 待审批/通知中按优先级组合成任务队列，提供明确的项目、进度或审批入口；无数据时显示可恢复的空状态。
5. **数据脉冲区**：保留近 6 个月支出趋势和人员支出构成，但改成连续的脉冲/条带视觉，图表只负责真实数据，不再被卡片框架切成两个平级营销模块。
6. **交付日志**：将最近填报作为带时间、任务编号、进度和备注的操作日志，保留原有真实字段与用户名称映射。

## 数据与行为

- `dashboardApi.summary()` 和 `dashboardApi.weekly()` 的请求契约不变。
- 刷新期间保留上一份成功数据，根节点通过 `aria-busy` 和状态线反馈；刷新失败显示旧数据及可重试提示。
- 首次加载、首次失败、局部 weekly 失败、空项目、空趋势、空支出构成均有明确状态，不以装饰性数据填充。
- 管理员显示“待审批”动作入口，普通用户显示“未读通知”；不把前端隐藏当作权限控制。
- 保留现有移动端 `MobileDock` 和抽屉契约；桌面首屏在 900px、767px、520px 断点逐层折叠为：状态读数横滑 → 介入队列 → 航迹列表 → 数据脉冲。

## 动效

- 初次进入只执行一套 authored moment：工作面建立、状态读数校准、项目航迹按序接入、介入队列显现。
- 航迹使用 transform/clip/opacity 等合成属性完成，避免动画改变布局；悬停只突出当前项目线和可执行入口。
- 刷新使用顶部链路状态和局部脉冲，不让整页重新入场。
- `prefers-reduced-motion: reduce` 下移除位移、路径绘制和连续呼吸，仅保留静态层级、焦点和文案状态。

## 可访问性与质量边界

- 保留语义化 `h1`、`h2`、链接、按钮、`role="alert"`、`aria-busy` 和进度条语义。
- 文案、金额、日期、百分比和状态沿用当前中文工具函数；不引入英文装饰标签。
- 高风险状态不只依赖颜色，通过文字、图标几何和可读状态名共同表达。
- 不触碰认证、会话、API、Login 页、移动端导航数据契约。

## 验收标准

- Dashboard 不再以四张 KPI 卡或主表格作为首屏结构。
- 首屏可在 3 秒内识别当前工作态势和需要介入的事项。
- 所有现有 Dashboard DOM 测试、单元测试和生产构建通过。
- 桌面与移动视图无横向溢出；长项目名、长任务名和空状态可读。
- Impeccable detector 对本次改动目标只剩已知的既有规则，新增 UI 不引入禁用模式。
