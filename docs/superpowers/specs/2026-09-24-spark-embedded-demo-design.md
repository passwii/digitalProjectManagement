# Spark 内置免登录演示站设计

## 状态

- 日期：2026-09-24
- 设计状态：用户已确认方案 A
- 目标项目：`web/`（Next.js 14 App Router）

## 目标

在当前数科云办公项目内增加 Spark 演示入口，并实现一个可公开访问、无需登录的 NebulaCloud 管理站 mock 演示站。演示站复用已采集的页面结构、设计档案和 mock 数据，供内部学习和演示。

## 方案

采用项目内独立路由 `/spark`，由独立的 Spark 页面壳承载管理站；不使用 iframe，不请求原 Coze 站点，也不复用数科云办公的业务 API。`/spark` 及子路由加入现有 middleware 公共路径列表，因此没有主项目会话时也能直接访问。

数科云办公桌面侧栏增加 `Spark` 分组和 `NebulaCloud 演示站` 入口。该入口属于纯本地演示导航，不扩展后端 `/meta/me/menus` 权限契约。主项目现有登录和业务路由权限保持不变。手机端在现有「我的」抽屉中增加同一演示入口，保留五位底部 Dock 的既有契约。

首次打开 `/spark` 直接呈现管理总览，不呈现原站登录页。Spark 内部导航覆盖采集到的八个后台模块：运营总览、连锁门店、算力调度、计费收银、内容与赛事、安全合规、运维工单、权限管理。所有演示数据在本地静态 fixtures 中维护；页签、筛选、搜索、策略开关、滑块和导航等代表性交互只更新前端状态。

## 设计依据

- `ui-study/README.md`：页面地图、交互记录和归档内容。
- `ui-study/analysis/replication-blueprint.md`：深色控制台、青紫强调色、玻璃卡片和模块顺序。
- `ui-study/mock-content/mock-copy.json`：去重后的文案和源码出处。
- `ui-study/raw/*.json` 与 `ui-study/assets/`：页面结构、mock 数据和本地源码参考。

视觉采用独立作用域的深色控制台：底色 `#070a12`、侧栏 `#0a0f1c`、青色主强调、紫色辅助、语义状态色和半透明卡片。样式不修改主项目的全局视觉 token。图表使用项目已安装的 Recharts，避免新增运行时依赖。

## 页面与组件边界

- Spark 应用壳：品牌区、模块侧栏、顶部状态区、折叠/移动端导航和内容框架。
- 总览页：KPI、营收趋势、健康度、GPU 资源、地区营收、告警和排行。
- 门店页：区县/状态筛选、统计和门店卡片。
- 算力页：节点表、调度策略、弹性伸缩和套餐。
- 计费页：收入构成、支付渠道、规则和子页签。
- 内容页：游戏内容、分类搜索、分发和赛事子页签。
- 安全页：合规指标、策略开关、审计日志和容灾信息。
- 运维页：服务健康、工单状态筛选和 SLA 指标。
- 权限页：成员、角色筛选、角色权限和操作日志。
- Spark mock fixtures：每页展示所需的静态记录、指标、枚举项和图表序列。

路由使用 `/spark` 作为总览入口，并以 `/spark/dashboard`、`/spark/stores`、`/spark/compute`、`/spark/billing`、`/spark/content`、`/spark/security`、`/spark/ops`、`/spark/permission` 支持刷新和深链。

## 登录与数据边界

- Spark 页面及所有子路由不要求 `pm_access_token`。
- 主项目侧栏在主项目已有登录会话时显示 Spark 入口；未登录用户可直接访问 `/spark`。
- Spark 只读取随前端发布的本地 mock fixtures，不访问数科云办公 API、原站 API 或数据库。
- 原站登录页面及其演示凭据不进入 Spark 可见界面。
- 原页面中的演示数据继续标识为 mock，不表达实时业务状态。

## 响应式与无障碍

- 桌面端提供可折叠的 Spark 侧栏与完整内容区。
- 窄屏将模块导航切换为可打开/关闭的抽屉，内容卡片纵向单列。
- 导航和控件可通过键盘操作，当前路由使用 `aria-current`；减少动态效果时尊重 `prefers-reduced-motion`。

## 验收标准

1. 清除会话后直接打开 `/spark`，页面仍显示总览；刷新 `/spark/<module>` 保持当前模块。
2. 登录主项目后，桌面侧栏中出现 Spark 分组和演示入口，点击进入 `/spark`。
3. 手机端可以从「我的」抽屉进入 Spark，同时 Dock 仍为五个位置。
4. 八个模块均可从 Spark 内部导航到达，主要信息结构和 mock 文案对应学习档案。
5. 已归档的筛选、页签、开关、滑块等代表性交互可操作并立即反映在 UI 状态。
6. Spark 样式被局限在 Spark 壳内，主项目现有页面样式与权限菜单契约不变。
7. Spark 浏览期间没有对原 Coze 域名或主项目业务 API 的请求。

## 不在本次范围

- 连接任何真实 API、数据库、账号认证、权限保存或跨会话数据持久化。
- 重建原站登录页。
- 改造主项目现有五位手机 Dock 结构或后端菜单契约。
- 对未记录的演示按钮添加真实业务语义。
