# 项目台账应收与回款升级设计

> 日期：2026-09-29
> 来源：`OA升级.docx` 的项目台账改动建议及后续确认
> 状态：已确认，进入实施

## 目标

在项目详情中增加独立应收子账，按单笔应收跟踪多笔回款、已收金额、未收余额与回款状态；同时调整成本/日志页签文案，并将项目年份筛选限定为 2023 至 2027。

## 已确认范围

- 项目详情中的“支出”页签改名为“成本”，其数据、支出审批与全局支出页面保持不变。
- 在项目详情增加“应收”页签；“变更”页签改名为“日志”，内容仍是项目字段变更记录。
- 应收与财务模块隔离，不读取或写入财务应收凭证，不自动导入历史财务应收。
- 年份选项固定为 2023、2024、2025、2026、2027；其他历史链接年份回落为全部年份。

## 数据与业务规则

- `project_receivables` 保存项目、款项/阶段名称、应收金额、应收日期、必填到期日、说明、创建/修改人及软删除信息。
- `project_receivable_payments` 保存所属应收、回款金额、回款日期、备注、创建/修改人及软删除信息。
- 金额使用 `NUMERIC(18,2)`；应收与回款金额均须大于零。回款累计不得超过应收金额；应收金额不得修改到低于有效回款累计。
- 已收金额由未删除回款汇总，未收余额为应收金额减已收金额，不另存可漂移的汇总值。
- 状态按北京时间当前业务日实时派生：已足额回款为“已收清”；未收清且当前日晚于到期日为“逾期”；其他情况下按累计回款区分“未回款”和“部分回款”。到期日当天不算逾期。
- 每笔回款单独留痕。所有新增、修改、软删除与回款操作写入审计日志；软删除不物理级联清除回款历史，已删除回款不计入余额。
- 读操作复用项目可见范围；新增/修改/登记回款须有项目写权限（管理员或项目负责人/成员）；软删除仅管理员。已归档项目只读。
- 回款和应收金额修改以项目行锁串行化，服务端在事务内重算有效回款，防止并发超收。

## API 与页面

- 新增项目级应收 API，提供应收列表、新增/修改/软删除，以及应收记录下的回款列表、新增/修改/软删除。
- 金额响应使用固定两位小数字符串，避免 JSON 浮点误差；日期使用 ISO `YYYY-MM-DD`。
- 项目详情增加“应收”页签，展示应收金额、累计已收、未收余额、到期日、状态和说明，并可查看逐笔回款。
- 具有项目写权限的用户可新建/编辑应收、登记/更正回款；仅管理员显示删除操作。桌面表格和窄屏卡片都支持核心查看流程。
- 年份筛选仅显示五个固定年份；`?year=` 旧链接中不在范围的年份转为不筛选。

## 非目标

- 不产生会计凭证，不接入财务应收、收款、核销、账龄或对账单。
- 不批量迁移/导入历史财务应收。
- 不重命名全局支出、审批、财务或报表中的支出用语。
- 不把“日志”扩展为全站操作日志。

## 验收

- 后端验证金额、日期、项目权限、归档只读、软删除过滤、审计留痕与并发回款上限。
- 前端验证五个年份选项、旧年份与旧页签链接兼容、应收/回款录入交互和状态/汇总展示。
- 运行定向测试、前端完整测试、后端可用测试及静态检查；数据库集成测试若缺少 `TEST_DATABASE_URL` 必须明确报告为跳过。
