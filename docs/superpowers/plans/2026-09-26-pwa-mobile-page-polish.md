# PWA 手机页面系统打磨实施计划

> **执行约定：** 按任务逐项完成并更新勾选状态；每一项保留现有业务、权限、URL、桌面布局与既有视觉语言。

**目标：** 让所有 PWA 路由在手机上能清楚地阅读、筛选和完成主要操作，避免横向表格、窄触控区和软键盘遮挡造成的阻塞。

**架构：** 先修共享的页面标题、筛选、卡片、表格与弹层规则，再按业务频率处理各路由。表格密集的财务与报表保留完整数据口径，按任务需要提供手机摘要或明确的横向浏览；桌面布局保持原样。导航仍由权限菜单与现有五位 Dock 决定。

**技术栈：** Next.js 14 App Router、React 18、TypeScript、CSS Modules、现有 `CardList` / `PageHeader` / `Modal` 组件。

## 全局约束

- 断点沿用 767px；手机触控目标不小于 44px，输入字号不小于 16px。
- 保留深浅主题、减少动效、焦点、系统安全区和全站下拉刷新。
- 不修改 API、数据口径、权限判断、业务写入流程及 URL 状态。
- 遵守 `docs/superpowers/specs/2026-09-18-mobile-pwa-navigation-design.md` 与 `docs/superpowers/specs/2026-09-26-mobile-pwa-refresh-dock-design.md` 的现行契约；其中 Dock 以 9 月 26 日单档面板设计为准。
- 优先解决任务阻塞和可访问性，再处理视觉密度、间距与文案。
