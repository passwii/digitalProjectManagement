# 应收应付账龄与对账单实施计划

> **面向执行代理：** 按本计划逐项推进；步骤使用复选框跟踪。实施遵循测试驱动开发。

**目标：** 财务工作台基于本工作台登记且已过账的凭证展示应收/应付账龄与客户/供应商对账单，并只允许新建人民币账套；明确披露普通凭证与期初辅助余额尚未纳入。

**架构：** 以 Voucher 的 `posted` 状态作为正式账务事实；结合 ARAPTransaction 与 ARAPAllocation 生成按凭证日期排序的单据及核销流水。报表范围只覆盖应收应付工作台登记的单据和核销，暂不包括普通手工/模板/导入凭证及期初辅助余额，界面需说明范围。前端经现有 `financeApi` 读取只读报表，不新增数据库表。

**技术栈：** FastAPI、SQLAlchemy、PostgreSQL、pytest、Next.js、React、TypeScript、现有 Finance API 与财务工作台组件。

## 全局约束

- 财务产品币种为 CNY；数据库兼容字段保留，不提供汇率、多币种或调汇流程。
- 正式账龄/对账只纳入 `posted` 凭证；草稿、待审核和作废不进正式余额。
- 账龄按凭证日计算，不代表合同逾期日；不按账龄档自动生成坏账准备。
- 金额使用 `Decimal` 并以十进制字符串序列化；所有读取按 `X-Account-Book` 隔离。
- 对账单为财务核对输出，不标记为税务申报表；税率和预期信用损失参数不硬编码。
- 不将当前工作台口径称为完整往来辅助明细账；完整口径需另阶段统一纳入普通凭证辅助核算和期初辅助余额。
- 对账单分页当前在应用层完成；流水量增长后需下推筛选、汇总和分页到数据库。
