# 手机 PWA · 底座导航草稿

## 文件

- `index.html`：可直接打开的移动端 PWA 草稿（桌面会显示 390×844 手机框 + 草稿控制面板）
- 默认深色；右上角草稿面板可切浅色
- 点底部「更多」查看底部 sheet；点「全部入口」也会打开

## 方向

- 手机端导航从顶部移到底部，固定为 6 槽：工作台 / 项目台账 / 进度跟踪 / 支出记录 / 审批中心 / 更多
- 5 个主入口与桌面药丸导航保持一致；其余入口进「更多」sheet
- 顶栏只保留品牌、通知、账号，不再承担主导航
- 内容区为 dock + `env(safe-area-inset-bottom)` 让位；PWA standalone 使用 `100dvh`
- 每个 dock 触控目标 ≥ 44px；当前项用液态玻璃胶囊高亮

## 需要确认

1. 手机首页保留这版「问候 + 4 张入口卡」，还是继续沿用桌面隧道欢迎页？
2. 账号入口放在顶栏右上，还是收进「更多」sheet？
3. 6 槽（5 类 + 更多）是否接受？还是只保留 4 个主入口 + 更多？
4. 通知入口是否继续放在顶栏？未读数是否需要在 dock 上再给一个入口？
5. PWA 安装提示是否在首次进入时出现？出现在工作台还是登录后？

## 实施提醒（给后续 subagent）

- 不要直接改生产代码；先以本 HTML 为视觉基准。
- 桌面保持现有居中液态导航；≤767px 切换为底部 dock，避免两套导航同时出现。
- 处理 `env(safe-area-inset-bottom)`、`100dvh`、iOS standalone、横屏短屏。
- More sheet 需要焦点陷阱、Esc 关闭、返回焦点到「更多」；触控滚动与 `overscroll-behavior` 要验证。
- 现有 `MobileDock` 组件可复用交互与可访问性逻辑，但视觉要按本稿重做。
- 账号/通知入口必须保留：当前实现中 Bell 是唯一通知列表入口，移动端不能直接删掉。
