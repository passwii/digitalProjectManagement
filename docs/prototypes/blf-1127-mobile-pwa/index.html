信息架构：桌面 7 个入口 → 手机 5 个 Dock 位

桌面侧栏现在是 工作台 / 项目台账 / 进度跟踪 / 支出记录 / 支出报表 / 通讯录 / 审批中心 / 系统管理， 最多 8 项。手机 Dock 最多 5 位，硬塞会把标签压成 9px 不可读，因此按「业务对象」而不是「页面」分组：

① 「支出」合并「支出记录 + 支出报表」不是偷懒——两者是同一个业务对象（支出）的录入面与汇总面， 在手机上并排做两个 Dock 位反而让用户每次都要先想「我要的是记录还是报表」。合并后 D 位只占 1 格，报表作为抽屉里的第二张卡进入。 这里叫「支出」而不是「费用」：/meta/me/menus 与页面文案（支出日期 / 支出金额 / 暂无支出）里只有一个词。

展开形态：卡片（peek）与抽屉（half / full）是一套三态，不是两种控件

同一张底部面板，按拖拽停靠位分三档，手势语义与 iOS 地图/Safari 一致：

档位高度遮罩内容用途
peek自适应（≤180px）无2–4 张预览卡选中 Dock 的默认档：不打断当前页，一眼看到「有什么、要不要进去」
half56%有卡片列表 + 筛选需要比较几条记录时
full整屏（保状态栏）有列表 + 分页当筛选/详情必须全屏时，等价于进入模块列表
点 Dock → 直接进 peek，不跳页 再点当前 Dock → 收起到 peek 上拖 → half → full 下甩 / 点遮罩 → 关闭 点卡片 → 进模块或详情

为什么是「抽屉里放卡片」

  1. 抽屉解决纵向层级（快捷面板与当前页共存），卡片解决横向信息密度（每张卡就是一条业务结论）。
  2. peek 态不遮内容、不加遮罩，用户可以「看两眼就走」，这是手机端最高频的诉求。
  3. 需要深挖时手势上拖升级为 half/full，不需要重写第二套组件——与现有 components/ui/Modal.tsx 的 Drawer 复用同一套焦点与 Esc 逻辑。

登录页：从「上重下轻」改为真居中

现状手机端是桌面 story 竖排——顶部深色大标题占掉半屏，表单被推到下面，需要抬手甚至滚动。改动：

  1. 手机端只保留垂直居中的品牌块（印章 + 字标 + 一句话），删掉桌面的大标题与 01/02/03 卖点行。
  2. 表单组（输入 + 错误 + 按钮）用 justify-content:center 光学居中——居中基准是表单组而不是「品牌块 + 表单」，否则表单会偏下。
  3. 输入框高度 46px、字号 ≥16px（iOS <16px 会自动缩放页面，是手机端最常见的「莫名放大」来源）。
  4. 软键盘抬起时用 visualViewport 把表单上移，错误提示与主按钮始终可见；密码框回车直接提交。
②桌面 login.module.css 的 @media (max-width:980px) 只把两栏改成一栏，属于「窄屏适配」；本轮要的是手机端专属布局，建议按 <768px 走独立分支并保留 story 的品牌资产（底色、网格、印章）。

已定稿的 4 个决策（D1–D4）

D1 Dock 第 4 位叫「支出」

合并保留（支出记录 + 支出报表 = 同一业务对象的录入面 + 汇总面），只改名。依据：/meta/me/menus 返回「支出记录」「支出报表」，页面文案用「支出日期 / 支出金额 / 暂无支出」——「支出」是唯一存在过的词。路由键仍为 costs。

D2 peek 保留预览卡，点 Dock 不跳页

再点当前位收起、half/full 降回 peek；不做长按手势。点 Dock 直接跳页会把 Dock 做成一个更慢的侧栏，也丢掉「展开来是卡片或抽屉」这条原始需求。

D3 管理员入口留在「我的」抽屉

Dock 恒定 5 位、不随角色变形（肌肉记忆一致）；待办红点挂在「我的」Dock 位上。管理员是少数角色，为它多开第 6 位不划算。

D4 表格页手机端改卡片流

本轮只覆盖项目台账（/projects）/ 审批中心（/approvals）两页，一屏 2–3 条可读结论；桌面 table.grid 不动。其余表格列为后续。
