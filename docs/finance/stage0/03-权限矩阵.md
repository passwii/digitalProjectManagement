# 权限矩阵（冻结版，P0-D 落地，后端强制校验）

## 1. 四层模型

| 层 | 控制对象 | 说明 |
| ---- | ---------- | ------ |
| L1 账套层 | `account_book_id` | 无授权账套的一切财务接口返回 403；列表查询自动过滤 |
| L2 期间层 | `accounting_periods.status` | `closed/locked` 期间只读；`open` 期间按角色可写；调整期须额外 `period:adjust` 权限 |
| L3 模块层 | 功能模块 | 总账/凭证/出纳/报表/结账/基础资料/税务/审计，按角色授予 read/write/approve |
| L4 字段层 | 敏感字段 | 金额、税率参数、工资明细、身份证号：脱敏或不可见（`field:mask`） |

**红线**：前端隐藏按钮不是安全边界；所有越权必须在后端拦截并审计。

## 3. 不相容岗位矩阵（后端硬校验，违反直接拒绝并审计）

| 互斥对 | 规则 |
| -------- | ------ |
| 制单 ≠ 审核 | 同一凭证 `created_by` 不得等于 `reviewed_by`（DB CHECK） |
| 出纳签字 ≠ 过账 | 同一付款凭证的出纳签字人与过账人不得为同一人 |
| 结账人 ≠ 本期制单人 | 本期间有制单记录的用户不得执行本期间结账 |
| 审核人 ≠ 出纳（同笔资金） | 资金类凭证审核与出纳签字分离 |
| 参数维护 ≠ 参数审批 | 税务政策 `version` 的录入与 `effective` 审批分离 |
| 审计查询 ≠ 业务操作 | 审计员角色禁止一切业务写操作 |

## 4. 高风险操作审批链

反结账、删除账套、批量作废、税务参数生效、调整期凭证：
`提交 → 财务主管审批 → 执行`，全链路审计留痕；反结账另需二次确认。

## 5. 审计要求

- 审计日志追加-only：业务账号无 DELETE/UPDATE 权限（DB GRANT 隔离）。
- 记录变更前后值、操作人、IP/设备、时间；导出/下载同样审计。
- 留存 ≥ 10 年；独立备份；与业务库分离存储（P0-D 落地，现有 `AuditLog` 同库现状必须整改）。
